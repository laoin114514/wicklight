# WICKLIGHT · 灯芯

俯视角**暗夜生存动作肉鸽（Roguelite）**。核心是同一个资源承担两种职能：

> **你的灯火，既是视野，也是火力。**

灯越亮，照亮的范围越大、伤害越高、自动索敌越远；但灯油会持续燃烧，亮度越高也越吸引敌人。
击杀敌人回充灯油——于是每一秒都在「恋战」与「保命」之间做取舍。灯油耗尽时灯火熄灭，
在黑暗中缓慢失去生命：你必须一直狩猎，才能一直发光。

## 快速开始

```bash
npm install
npm run dev        # http://localhost:5173
```

构建 + 本地静态预览（产物在 `dist/`）：

```bash
npm run build
npm run preview
```

零依赖降级方案（无需 `npm install`，只需 Node ≥ 18）：先 `npm run build`，再 `npm run serve`
或 `npm start`（构建 + 内置静态服务器）。

## 操作

| 动作 | 键盘 / 鼠标 | 手柄 |
| --- | --- | --- |
| 移动 | `W A S D` / 方向键 | 左摇杆 / 十字键 |
| 射击 | **自动索敌开火**（光照范围内自动攻击） | 同左（不用按键） |
| 冲刺（含无敌帧） | `空格` / `K` / `Shift` | `Ⓐ` / `RT` |
| 燃爆（范围清场，消耗灯油） | `Q` / `J` / 鼠标左键 | `Ⓧ` / `LT` |
| 分灯（放下一盏小灯，引开黑暗） | `E`（手机：右下角的「分灯」键） | `Ⓑ` |
| 拨芯（把灯芯拨小 / 拨回来） | `C`（手机：右下角的「拨芯」键；它是**开关**，按一下翻一格） | `Ⓨ`（同样是开关） |
| 倾灯的手动瞄准 | **按住鼠标右键**（指针指哪儿倒哪儿；指针离人越远落得越远） | 右摇杆（推多远落多远） |
| 暂停 | `Esc` / `P` | `Start` |
| 构筑总览（武器 / 遗物 / 被动 / 夜咒 / 关键属性） | `Tab` | `Back` |
| 升级面板：选第 n 张卡 / 重掷 | `1` `2` `3`（小键盘也算）/ `R` | `Ⓐ` `Ⓑ` `Ⓧ` `Ⓨ` = 第 1~4 张 / `Back` 重掷 |
| 祭坛：选第 n 件供物 | `1` `2` `3` | `Ⓐ` `Ⓑ` `Ⓧ` = 第 1~3 件 |
| 商店：买第 n 件 / 刷新货架 | `1` … `6` / `R` | `Ⓐ` `Ⓑ` `Ⓧ` `Ⓨ` = 第 1~4 件、`LB` / `RB` = 第 5 / 6 件 / `Back` 刷新 |
| 夜咒岔口：选第 n 条夜咒（带走的那一条不可逆） | `1` `2` `3` | `Ⓐ` `Ⓑ` `Ⓧ` = 第 1~3 条 |
| 结算面板：点那颗主按钮（再点一盏 / 挑战无尽之夜） | `回车` | `Start`（结算屏上它只认这颗按钮） |
| 战斗之外的每一屏（菜单 / 选灯火 / 图鉴 / 档案 / 成就 / 设置 / 解锁树 / 今日灯芯 / 暂停）：**挪焦点环 / 按下 / 返回** | 方向键挪环、`回车` = 环上那一项（环没亮时 = 那一屏的主按钮）、`Esc` = 返回 | 十字键 / 左摇杆挪环、`Ⓐ` = 环上那一项、`Start` = 主按钮、`Ⓑ` = 返回 |

移动端：**必须横屏**——竖着拿会盖一块「把手机横过来」的牌子（同时停掉主循环，不白烧电），
横过来自动消失，牌子上那颗「全屏并横屏」按钮在安卓上会直接进全屏并把屏幕转过来；
左半屏虚拟摇杆（带 12% 死区，手指搭在上面不会让角色慢慢漂）+ 分灯/冲刺/燃爆三枚按钮（自动开火）；
**倾灯的手动瞄准**：手指按住**屏幕右侧**拖动，这一瓢就「往你指的方向倒」——方向与距离都归你
（推得越远落得越远，最近落在脚前 35% 射程处，正好够把这一瓢补在自己刚倒的那片火上），
脚下会出现一个小扇面、落点上一圈**和那片火一样大**的圆：上膛（油够 + 冷却转完）时整圈亮起来，
没上膛是暗的。**松手就还给自动瞄准**——不按的时候这一件和以前一模一样。
它挂的是 window 上的一块"屏幕区域"，不是第四枚按钮：右侧那块地方上压着 HUD 与三枚按钮，
844×390 中间只剩 110px 高，挂一个元素上去要么盖住按钮、要么小到按不准；
两个按钮外缘有**冷却圈**：亮的那半是"已经转回来了"，暗的那半是"还差多少"（转好了整圈消失，
没圈 = 随时能按），冲刺中还会给一圈青光——那 0.3 秒的伤害无效帧本来在手机上完全看不见；
按钮按下会**短震一下**（设置里可关，iOS 上没有这个 API 就安静跳过；
系统手势 / 来电打断触摸时按钮会立刻松开，不会卡在"一直按着"）；
**战斗触感**也走同一条路：挨打 12ms 一下（220ms 节流，被围殴时不会连着震）、
血量首次跌破 25% 来一段"心跳"（回到 35% 以上才重新武装）、升级是 18-50-18、
死亡 160ms——手机上两只拇指都压在屏幕上，血条长在视野角上，手是唯一空着的反馈通道；
摇杆与三枚按钮**只在战斗中上屏**——菜单 / 暂停 / 升级 / 商店这些面板和它同一层，
一直挂着会盖住面板右下角的按钮、把点击吃掉（844×390 的主菜单实测：那两枚圆按钮正压在"成就 / 设置"上），
切出战斗时会连"还按着的手指"一起松开，恢复后角色不会自己往前跑；
右上角记分栏边上有一枚**暂停键**（命中圈 48px、里面画 36px 的圆：手指点得中，视觉上也不顶到记分栏）——
手机上没有键盘的 Esc，这是唯一能打开暂停面板的入口，
构筑总览就在那里面（它绝对定位挂在记分栏外侧，不参与排版，所以不会挤到任何芯片）。
**返回键守卫**：横屏时浏览器左边缘那道侧滑手势带正好压在左手拇指的活动范围里——
正往左跑着，一个侧滑就离开页面，这一局直接没了。所以战斗里会往历史里塞一条守卫条目，
让返回键（侧滑）先撞在它上面：撞上就是**暂停**，走不走由玩家自己决定；
离开战斗会立刻把这条吃回去，不会攒成一串历史让玩家为了退出按好几次返回。
桌面上整段不装（键盘玩家的 `Alt+←` 本来也不会误触）。
装到桌面（PWA）后走 manifest 的 `display: fullscreen` + `orientation: landscape`，直接全屏横屏。
打起来会申请 **Wake Lock**（屏幕常亮），手离开屏幕看血条时手机不会自己息屏；
暂停 / 竖屏 / 切后台都会立刻放掉。

**手柄（v81）**：这是第四条输入路，也是唯一一条**两只手都在同一块东西上**的路。
键盘上"走位 + 冲刺"归左手、"燃爆 / 分灯 / 拨芯"归右手，而那块留给"倾灯手动瞄准"的地方
只有鼠标右键（指针指哪儿倒哪儿——它没有起点，只能拿屏幕当行程）。手柄把这件事变成它本来就该有的样子：
**左摇杆走位、右摇杆瞄准**，推多远就是推多远（和触屏那根手指是同一个编码：方向 + 0~1 的力度）。
三条规矩：**① 一只手柄说了算**——同时插着两只时只认第一只（`getGamepads()` 的顺序），
不做"谁的输入大听谁的"，两只手在同一个角色身上抢方向盘只会让人以为游戏坏了；
**② 一次性输入做边沿检测**——分灯 / 拨芯 / 暂停 / 构筑总览，以及面板上那几下"按一下"，
都只在**按下的那一帧**给一次（少了这一步，按住一个键就变成每帧按一下：拨芯一秒翻 60 格、重掷把点花光）；
**③ 它按情境分家，和键盘一样**——手柄上就那么几个键，所以 `Start` 在战斗里是暂停、在面板上是确认，
`Back` 在战斗里是构筑总览、在面板上是重掷，正好就是键盘上那两对键（`Esc`/`回车`、`Tab`/`R`）的分法，
两个设备之间切换不会长出第二套直觉。
面板上就只有那么几个键，所以**商店的六件货架**这样分：四个脸键 = 第 1~4 件、肩上那两枚（LB / RB）=
第 5 / 6 件（正好是键盘那排数字键的位置）。顺带把键盘那条老账也补平了：数字键从前**只认 1~4**，
而货架一直是六件——最下面那两件（热汤 / 满壶灯油）永远得挪手去点鼠标，而那两件正好是"打残了先买一口"
的时候要按的，所以这一版键盘也认 `5` / `6` 了（文档里写的 `1` … `6` 到这一版才算真的是六件）。
**结算屏**（阵亡 / 通关）也只有一颗按钮（键盘的 `回车`），所以那一屏上 `Start` 就是它——
不然手柄玩家打到死就卡在结算屏上，只能去摸鼠标。
「倾灯」手动瞄准那三条路（触屏那根手指 / 右摇杆 / 鼠标右键）按"谁更明确"排优先级：手指按着的时候以触屏为准，
其次是推着右摇杆的人，最后才轮到鼠标——它没有起点、只能拿屏幕当行程，是三条里最含糊的一条。
摇杆的死区是 **18%**（触屏摇杆是 12%，手柄那只杆回中更不准，手搭在上面不该让角色慢慢漂）；
右摇杆（瞄准）的死区更大一点、**25%**——瞄准是"推出去才算在瞄"，推一点点就开始改落点像是在跟游戏抢那盏灯。
接上手柄的那一刻：底部那行常驻说明**换成手柄那一份**（手柄玩家看"空格冲刺"是没有用的），
第一次接上还会讲一次完整键位（同一条只讲一次，写进存档）；拔掉就换回键盘那一份。
手机上接蓝牙手柄（安卓上很常见）也是同一套——`body.is-touch .hud__hint` 平时把那行藏着，
手柄那一份靠 `is-pad` 露出来（藏的是"空格冲刺"，不该连手柄那行一起藏掉）。

**面板热键（为什么值得做）**：这一局的开火是自动的，手一直停在 `W A S D` 上——
可升级面板一局要弹三四十次，每一次都得把手挪到鼠标上点一张卡，节奏就在那儿被切断一次。
所以三块会**打断战斗**的面板（升级卡 / 祭坛 / 商店）都接上了键盘，选哪张、买哪件、
刷不刷新全都不必碰鼠标；结算面板上那颗主按钮是 `回车`（"我读完了"）。
数字键只认**当前那块面板**上的第几个位置（`1` … `6`：升级卡与祭坛只有三件，多出来的那两个数是留给
商店那六件货架的），`R` 是那一处唯一的"重掷"——
升级面板里是换三张卡，商店里是刷新货架。按错地方不会有任何副作用（这条有测试钉着：
战斗中按 `R` 不该白吃一次重掷、也不该悄悄扣掉 8 金币）。
键位与提示一起给：卡上的号码、按钮上的 `R` / `回车` 就是那几枚 `Tab` 提示的同一套小片，
手机上 `body.is-touch .key` 会把它们整片藏掉——那个环境里根本没有键盘。

**焦点环（v82）**：v81 把战斗接上了手柄，可"开一局"这一步仍然得摸一次鼠标——手柄没有指针，
"开始冒险"那颗按钮点不动，于是"战斗里彻底不用碰键鼠"这句话只成了一半。这一版补的就是这半条：
一个**焦点环**。方向键 / 十字键 / 左摇杆把环挪到某个按钮上，`回车` / `Ⓐ` 按下它，
`Esc` / `Ⓑ` 走这一屏的「返回」（`Start` 与 `回车` 同义，那十几屏上没有第二种意思）。
三条设计规矩，后面都有实测：

- **按几何挪，不按 DOM 顺序挪**：主菜单是两列、选灯火是网格、解锁树是三层的错位网格——
  只按元素顺序上下挪的话，玩家按"右"会跳到"下一行的第一个"。所以环按**屏幕上的位置**挑：
  先只看"侧轴投影和你交叠"的候选（那就是同一列），里面有东西就挑**最正对着你**的那个；
  一条都没有才退回按曼哈顿距离挑最近的一个。1280×720 上逐项跑四个方向量过
  （`/tmp/wl/navmeasure2.mjs`，直接调产物里那个纯函数，不抄一遍）：主菜单 19 下有同列候选、
  **0 下挑到别列**、其中 **5 下**和纯曼哈顿距离的答案不一样；选灯火 24 / 0 / 6；
  解锁树 64 / 0 / 7；设置 8 / 0 / 0；今日灯芯 2 / 0 / 0。
  "同列优先"是**构造性**的（同列候选存在时不可能挑到别列去），不靠像素差碰运气——
  第一版用的是"主轴 + 2×侧轴"那种加权距离，台架量出来**更差**（解锁树 38 下同列候选里跨列 6 下，
  加权之后 8 下），于是换成了现在这条结构性规则。
  同列里"谁算正下方"另有一层：主菜单那颗 425×97 的大按钮底下并排着两颗（无尽之夜 / 每日灯芯），
  两个到它的曼哈顿距离只差两像素——只按距离挑等于抛硬币（实测按键会有一半概率落到偏右那颗上），
  所以同列候选再按"侧向偏得少"排一次，按"下"就永远是正下面那一颗。
- **按住会自己走，先慢后快**：第一下立刻走一格，按住超过 **0.35 秒**之后每 **0.11 秒**一格。
  菜单里挪三格不该按三次；也不能一按就冲到对面（0.11 秒是"一格一格看得清"的下限）。
- **环只在用键盘 / 手柄时才亮**：第一次按方向才出现（手机上根本没这东西，一直挂着会让人以为
  那里有个能点的东西），**换一屏也收掉**——不收的话它会"记得"上一屏的第 4 项，
  于是从图鉴按 `Esc` 回菜单时，没按方向右边那一列就挂着一圈光（实测就是这个症状）。

写这一版撞出来的那个 bug 值得记一笔：环靠"这一帧的方向和上一帧不一样"认出"这是一下新的"，
于是"只在有方向时才喂给它"的写法会让"哒、哒"两下同方向的轻点里的第二下被吃掉
（间隔 60~70ms，远不到 0.35 秒的重复门槛，而人手在菜单里连点两下就是这么快）。两处改动收掉它：
`Input` 把"这一帧按下的那一下"也算进方向（一帧 16.7ms、手机档 30fps 是 33ms，而一次轻点只要 20~40ms——
那一下完全可能整帧落在 `keydown` 与 `keyup` 之间），主循环则**每一帧都喂**（含 (0,0) 那几帧，
环靠它知道"松手了"）。离线那套也照着补了：桩件（`tests/dom-stubs.mjs`）现在能塞一份"可点的东西"进去，
于是"真键盘事件 → Input → 主循环 → 环 → 元素的 click"这整条路在无头环境里也走得通。

手柄这一头多了一个 `menu` 情境（主菜单 / 图鉴 / 设置……那一批）：脸键不再是"第几张"而是
"按下焦点 / 返回"，`Start` 是这一屏的主按钮，十字键与左摇杆给方向。
摇杆那个死区比走位大得多——**45%**（走位是 18%）：菜单上"手搭在杆上"是个**静止**动作，
回中不准的杆会一直报 0.2~0.3，那个量级够把环一格一格推走。
要不要用环由**你按不按方向**决定，鼠标悬停不会挪它（`hover` 与 `focus` 是两回事，
所以那十几屏上鼠标、手指、键盘、手柄四条路并存，各走各的）。

## 玩法系统

- **灯火（4 位角色）**：守夜人（环形火环·灯油更耐久）、灯语者（追踪火苗·掉油更多）、
  焚烬者（爆裂火球·亮度增伤）、暗行者（烈焰鞭·身法快但灯火更暗）。后三位需用余烬解锁。
- **掠影（擦着危险走过去）**：这一局里**开火是自动的**——枪法不构成技巧，玩家剩下的技巧只有走位。
  可走位在原来的规则里只有惩罚没有奖赏：贴得近就是挨打，躲得远就是安全，于是"离得越远越好"
  成了唯一解，打得再久，高手和怂人的操作看起来也一模一样。
  掠影把"擦身而过"变成资源：贴着敌人或弹幕**擦**过去（进了判定的边、但没被判定吃到）热度就往上走、
  还回一点灯油——脚边那圈符文会长起来。三条规则，缺一条这个机制就会坏掉：
  **① 要在动**（站着不动不算——否则"缩在怪堆里不动"会变成最省力的刷法，正好和它想鼓励的事相反）；
  **② 看有多贴**（热度按"离判定边有多近"**每秒**累加，不是"擦到就发一笔"——判定发生在刚进带子的那一瞬，
  而那一瞬的距离永远正好等于带子宽度，按次发钱的话"贴着判定边掠过"和"从最外沿溜过"给的一样多，
  "敢贴多近"就没被奖励到）；**③ 一物一次、黏着不算**（同一只怪 0.55 秒才记一次数，
  而且贴超过 2.4 秒之后它的贡献一路归零——离线脚本实测过，只按距离累加的话，
  绕着最慢的那只怪转圈，五分钟能点着 41 次焰）。
  攒满点着一阵 **「灯焰高涨」**（6 秒）：灯火半径 +30%、伤害 +25%、移速 +8%，
  自动索敌跟着灯的范围一起变远；代价是火烧得旺，**灯油多烧三成**——
  于是它不只是一段爽，也是一段"得赶紧杀点什么回油"的时间。烧完只留一半热度，
  不会在最密的怪群里一发接一发。冲刺里从弹幕**正中**穿过去是另一条路：那 0.32 秒的无敌帧
  以前只用来逃命，现在穿过去会给一笔顶得上"贴着擦一整秒"的热度（一次冲刺只认一次，
  这颗子弹也不再重复计数）。
- **焰路（把掠影接进构筑）**：机制本身不会变成"决定"——不管拿了什么，热度涨多快、焰烧多久、
  擦一次回多少油都对所有人是同一套数，于是"贴着打"只是一种**风格**。这一版补的是**取舍**：
  - 四件遗物各改一个数，而且正好一族一件：**焰心**（攒热快 45%）、**长风**（焰 6 秒变 9 秒）、
    **撩芯**（擦身回的那口油翻倍）、**影缝**（焰里受到伤害 -30%）。它们乘的是同一条算式，
    单拿一件改变不了走位，凑起来才成为一种打法；散着拿也不亏，因为每件本身都在补一族的份数。
  - **焰里击杀续焰**：每杀一只怪给这一阵焰续 0.3 秒，最多续到基础时长的 1.5 倍（6 秒 → 9 秒）。
    焰是自己擦出来的，让它**烧下去**的却是击杀——于是"灯焰高涨"不只是擦满之后的六秒，
    而是一段"这六秒里得一直有东西倒下"的时间：停下来喘口气，焰就自己烧完了。
  - 两张**掠影悬赏**（本关掠影 30 次 / 点着 2 次灯焰高涨），第二关起才进池——
    第一关玩家还没见过这个机制（第一次擦到才会弹那张说明卡），开局就派一张看不懂的作业只会添堵。
  - 图鉴多一章**「机制」**，掠影与灯焰高涨各一条，数值直接从 `data/graze.ts` 现取，改调参时不会写漂。
  - 构筑总览里多一栏**掠影**：本局擦了多少次、点着几次、现在攒到哪儿，以及身上那四件到底改了哪个数
    （烧着的时候整块透出暖光，写的也从"热度 n/22"换成"还剩几秒"）。
- **伏灯（把"位置"埋进地里）**：掠影奖励"贴着走"，伏灯走的是反方向的另一头——**事先把东西放在那儿**。
  开火与瞄准都是自动的，所以位置本来就是玩家唯一握着的东西；到这一版为止它只被用来躲（离远点）
  和擦（贴着走过去），伏灯是第三种用法：跑着跑着往**身后**撒一颗雷（站着不动时绕自己撒一圈）。
  它先**上弦**半秒，这半秒踩不响、脚边画着一圈合拢的进度弧——刚放下就炸的话，它是手雷不是陷阱；
  上弦之后谁踩上来就炸一圈，进化的那颗还留一片火。几个数各管一件事：
  - **触发量的是"怪的边缘"**（判定时再加一次怪自己的半径），所以石守那种大块头会比影蛭更早踩响——
    它不是"被碰到"，是"自己走过来"；上弦之后地上会画出虚线触发圈，它管多大一片看得见。
  - **寿命 10 秒、地上最多 6 颗**：所以它铺不出一条雷带，只能在几处各埋一个"等一等"。
    这个 10 是被台架量出来的（见下面的「已知取舍」）——8 秒时追兵还没走到，雷就烧尽了。
  - **自己烧尽不炸**，不然"跑过去把雷耗掉"就成了一种清场手段；**炸了不伤自己**——
    这一局里玩家自己的爆炸从来不伤自己（火球也是同一条规矩），单独给它开例外只会让它在贴脸时不敢用。
  - **连爆**：一颗炸响时，离它"一颗爆炸半径"以内的其他伏灯会被引信点着，隔 0.09 秒顺着串烧过去。
    于是"把雷撒在哪儿"多了一层选择——撒得**密**（同一把枪一次撒下的两颗，间距 16px）
    就是把它们串成一颗大的；撒得**开**（两次开火之间隔着一两百像素，铺成一条路）就是一颗一颗地响。
    台架上（12 只追兵、60 秒、四种走位）满地雷的爆炸里有 **7%~50% 是被引信点着**的，不是被踩响的；
    最长的串（4 颗）出现在"回头穿过自己旧雷"的走法上，而一路不回头地跑（落点间距 p90 340px+）
    只有 7% 会串——"撒得密还是撒得开"这个选择是真的存在，而且真的改结果（详见「已知取舍」）。
    **一帧只响一颗，而且响的是离怪最近的那一颗**：雷密的时候一只怪常常同时站在两三颗的触发圈里，
    按数组顺序挑（先撞上最后摆下的那颗）会让爆炸中心飘到怪脚边之外，还会从两个方向同时点着邻居，
    把一串灯拆成两半——详见下面 `mine` 那一条的"踩过的坑"。
  满级 + 灼心 进化成**连珠伏灯**：一次撒两颗，炸完还在脚下留一片火，追兵踩上去是先被炸、再被烧。
  一串连到 4 颗以上会解「一串灯」，结算面板里也会写出这一局最长的一串。
  - **它是一盏灯，所以"它们扑的是光"这句是真的**：「灯蛾」的图鉴上一直写着"它们扑的是光，不是你"——
    这一版把这句话坐实：地上亮着的伏灯（上弦之后才算亮）在 380px 内会**把蛾拐过来**——
    蛾扑的是"最近的那盏光"，那盏灯比离你更近，它就改扑灯，扑到就自己把灯踩响。
    于是伏灯多了一种用法：**拿它当饵**，
    把一群蛾从你身上引开、再一起炸掉（一颗雷一次炸到 4 只解「以灯为饵」）。
    这一条只接在蛾身上：别的怪不会因为地上摆了雷就集体改道——不然摆一片雷就成了"把全场引开"的万能开关。
  - **它怕吹灯客**：走进你触发圈的**如果是吹灯客，那颗雷不炸**——它把你埋的灯吹灭了（不炸、不留火，
    只留一小撮紫烟）。伏灯唯一的天敌不是靠数值硬顶，而是把"你的触发圈"反过来用：
    它进得来，就吹得灭。所以埋在地上的一整条路它可以一边走一边给你掐灭——
    想用雷，就先把吹灯客点掉（结算面板里会写出这一局被吹灭了几颗，好让你知道有这回事）。
  - **四件遗物把"把它放在那儿"接成一套牌**（v77，和「焰路」「爆灯」「拨芯」「燎灯」「倾灯」同一个做法，一族一件）：
    它是这一局里唯一一件**把东西留在身后**的武器——买的不是伤害，是位置与时间。
    所以四个问题都长在这件事上，凑齐了是一句话：
    "铺一条路，把蛾引过来，踩响的走不动，而我早就跑开了。"
    **地上能等多久、能留几颗**（**灯阵**，长明：上限 6 → **8 颗**、寿命 10 → **13 秒**——
    台架上第 11 秒：裸装那颗早烧尽了，带灯阵的还在等，还剩 2.00s。抬的是上限，不是取消上限：
    这条规矩要拦的是"一路小跑铺出一条雷带"，多两颗只是让"铺一条路"做得成，不是让它变成唯一解）；
    **一串能串多远**（**接火**，焰火：连爆够得着的半径 +45%。台架上三颗雷按"半径 × 1.2 = 93.6px"
    排成一列（裸装只够得着 78px）：裸装只响 1 颗、地上剩 2 颗；带接火**一路烧过去 3 颗、地上剩 0 颗**——
    撒得开也串得起来，"排成一列"这件事第一次有了回报）；
    **那盏灯能把蛾从多远引过来、引来的蛾回了什么**（**香饵**，灯油：引蛾距离 **380 → 570px**、
    被炸死的灯蛾每只回 0.5% 油。台架上把蛾摆在一个"裸装闻不到、香饵闻得到"的位置（离雷 405px）：
    裸装它朝你来（405 → 432px），带香饵它**拐过去扑那颗雷**（405 → 341px）；
    油是按只算的：1 只回 0.500%、3 只回 1.500%（正好 ×3），不带这一件一口不回，
    而炸死在雷上的**影蛭**——不是蛾——也一口不回。饵做香了，蛾自己把油送回来）；
    **踩响之后它替你拦住谁**（**绊线**，暗影：炸到的那一圈移速砍一半、拖住 1.4 秒。台架上追兵踩响后

    这一族买的是"位置"，和那桶油没关系，所以它在构筑总览里有**自己的一栏**（撒了几颗、最长一串几颗、

- **旋灯（决定它们站在哪儿）**："位置"这件事到 v56 为止只有两个用法：**你**站在哪儿（躲 / 擦 / 掠影）、
  **东西**放在哪儿（分灯 / 伏灯）。旋灯是第三个，而且是反过来的那一个：**你决定它们站在哪儿**。
  扔出去一盏会转的灯（落点是自动瞄准锁着的那只怪，没人才落在你朝着的方向前面），它在 1.2 秒里
  把周围的东西往里拽，转完缩成一下炸。它是这一局里第一件**给别人打下手**的武器——
  伤害不高，用处在于把一群人拢到同一点，再让别的武器去打那一点：燃爆打的是半径、雷弧要跳、
  光矛要一条线、伏灯要一堆人踩在同一片地上，全都吃"它们站得有多近"。几个数各管一件事：
  - **吸力加在怪自己的速度上，不是把它定住**：中心是 175px/s，往外的衰减走 `(1 - d/R) ** 0.6`，
    而不是线性。这一条是 v58 改的：线性的时候，画出来的那道边界其实是**空头承诺**——半径 116 的圈里，
    0.86R 以内的一律被拽到中心，可 0.97R 那圈只挪 19px、0.99R 只剩 5px（看着进去了，其实一步不动）。
    把外侧垫起来之后，0.93R 以内一律收到中心、0.97R 还能挪 102px，只剩最外沿一道窄缝
    （0.99R 剩 39px）留给"贴着边跑过去"。中心那道力道一个数都没动，所以速度上的对抗照旧：
    疾影（132）在靠外的地方挣得开、影蛭（68）被拽着走、石守（34）只能被拖着走；首领从头到尾只挪 22px
    （约等于不动）。拽不动的东西才需要你换个想法——这是刻意的，副手武器不该是个"定身符"。
  - **首领几乎拽不动（22%）、精英拽一半（60%）**：那么大一块被拖着走只会显得假，
    而且一件副手武器也不该把首领按在原地——那是控场装的事，不是它的。
  - **收尾那一下没有击退**：它是用来拢人的，最后要是把人推开，等于自己把刚摆好的局面拆了。
    真正该疼的是下一发。
  - **收缩的爆炸半径只有吸入半径的 72%**：因为里头的怪已经被拽到中间了，小圈照样全中；
    而靠外没被拽动的（疾影、首领、逆着吸力往外跑的）就掉在圈外。这一条让"拢得多狠"和
    "炸得多疼"变成同一件事：吸力没起作用的那一发，收尾也跟着落空。
    画出来的旋臂会一路缩到**正好是那个爆炸半径**，所以"它要炸在哪儿"在收尾那几帧是看得见的。
  - **收网：把"拢住几只"变成它自己身上的一笔账**（v58）：收尾那一下的伤害 = 基础 + 6 ×
    这一下**真的打到几只**——数的是**收尾圈**里按住了几只（末尾还在往外挣的那些本来就不会被这一下
    打到，不该算进账里），然后头顶上飘出「收网 n 只 · 伤害」。为什么要补这一条：v57 的旋灯是纯铺垫，
    "拢得多好"在它自己身上看不出任何结果，玩家没有理由为了它去挑时机；现在一次十只就是 +60，
    差不多把这一发的底子（满级标称 68）翻了一倍。一次同时打到 10 只解「收网」，
    而且**门槛数的是只数、不是伤害**：伤害要乘上灯火（油满 ≈ 1.35 倍、烧干 ≈ 0.65 倍），
    同一个操作能差两倍，只数才不会飘；真按伤害算的话，进化那把（基础 166）空放一下都能白送。
    收成的那一下单独给了反馈：那一串字变金、变大一号，收尾那圈环从青的变成金的
    （同一个东西的两种状态，不是多炸一圈），音效也多一层往上走的亮音——
    因为 9 只和 10 只在画面上本来一模一样，玩家得看得出来自己离收成还差多远。
  - **它自己也点一盏灯**（168px / 0.44，比伏灯亮一档）：一是它本来就叫旋灯，
    二是被拽进来的怪、往里卷的弹幕、地上那道吸力边界，全都得在这盏灯底下才看得见——
    暗幕是 0.94 的一层，强度不够就等于画了个看不见的东西。
  满级 + 拾光 进化成**漩涡灯**：一次两盏（左右各偏一点，中间那一块也被拢住），而且**连弹幕一起卷**——
  卷到中心（吸入半径 × 0.2）就吞掉，那颗子弹再也打不到你。于是那条进化线的题眼是：
  从"拢怪"变成"替你挡一片"。两个成就一高一低：一个旋涡里同时拽住 6 只解「一网打尽」
  （数的是**吸力圈**——转的过程中拽住了几只），收尾那一下同时打到 10 只解「收网」
  （数的是更小的**收尾圈**——收的那一下按住了几只）。结算面板里会写出这一局转了几盏、
  最多一次拽住几只，以及「最狠的一网 n 只 · 伤害」。
  - **四件遗物把"你决定它们站在哪儿"接成一套牌**（v78，和「焰路」「爆灯」「拨芯」「燎灯」「倾灯」「伏灯」同一个做法，一族一件）：
    旋灯是这一局里唯一一件**自己不制造伤害**的武器，买的从来就是"位置"，所以四件都长在那一个动作上——
    而且和「伏灯」那一族（位置 = 攒起来等）不同，旋灯买的是**当下**那一下：
    圈多大、拢住的那几只好不好打、这一网收成什么、圈里的还走不走得动。

    台架上半径 200 → **236px**、转 1.2 → 1.5s；而收尾那一圈也跟着一起大：144.0 → **169.9px**——
    因为它是 `半径 × 0.72`，"拢得多狠"和"收尾多疼"从 v57 起就是同一个数，这一件只是把它放大，没有把它拆成两个数）；
    **被拢住的那几只好不好打**（**标灯**，焰火：圈里的敌人受到的**所有**伤害 +25%，离开那圈后还留 **0.5 秒**。
    台架上同一只靶：没拿这一件时圈里圈外一样疼（100.0 → 100.0）；带上之后圈里 **125.0**（正好 ×1.25），
    圈收完、那半秒也走完，回到 **100.0**。它刻意只放大"打出去的那一下"——
    灼烧是每帧从怪身上扣的、不经过 `applyHit`，所以不吃这 25%，和拨芯不吃灼烧是同一条规矩）；
    **这一网收成什么**（**榨油**，灯油：收网打到的**每一只**回 0.4% 灯油。台架上 1 只回 0.400%、
    3 只回 1.200%（正好 ×3），不带这一件一口不回；数的是"这一网真的打到几只"——
    它用的是收尾那一下的返回只数，和「收网」那枚成就同一个口径，不是"看着进了圈"）；
    **圈里的还走不走得动**（**缠网**，暗影：圈里移速 -35%、每帧续 0.4 秒。台架上同一盏灯、同一个起点：
    裸装圈里它自己走 68px/s、带缠网只剩 **44.2px/s**（×0.650），而"被吸着走"的那一份两边一模一样（117.6）——
    差出来的全是脚力；它走的是 `applySlow` 那条共用的减速账，所以和霜印那 0.5 倍撞在一起时**不会把人家顶回快的**，
    300px 外那只也一点没慢）。
    这一族买的是"位置"，和那桶油没关系，所以它在构筑总览里有**自己的一栏**（本局转了几盏、拢住过几只、
    收网最狠的一网几只，以及四件遗物各改了哪个数）——那一栏只在"手里有旋灯、或者挂着这一族的遗物"时才画，
    和「伏灯」那一栏同一个规矩。
- **弃灯（把这盏灯摆在哪一边）**（v83）：分灯（`E`）是这个游戏里**最老的一个动词**——v1 就有。
  它也一直是那个"什么都齐了、就差一件遗物"的机制：有教学卡、有手机按钮、有代价（一成四的油），
  可到 v82 为止，围绕它转的遗物**一件都没有**。于是它在手里一直是"偶尔想起来按一下"的东西——
  不是因为它弱，而是因为**没有任何一次选择长在它身上**。这一版补的就是这件事，一族一件，四个数：
  - **为什么值得一套牌**：这一局里开火与瞄准都是自动的，位置才是玩家真正握着的东西。
    「伏灯」买的是"事先放在那儿"（位置 = 攒起来等）、「旋灯」买的是"当下这一网"（位置 = 你决定它们站在哪儿），
    而分灯买的是第三种时间——**把它摆在我打算离开的那个方向**：怪回头走进那盏灯的光里，你往另一边去。
    三个动词各买一段时间，分灯买的是最短的那一段（几秒），也是最便宜的那一段（一成四的油）。
  - **它到底买到了什么（台架量的，`npm run bench:lamp`）**：12 只影蛭摆在身后 260px，玩家不还手，
    四种走位各跑 30 秒，放灯 / 不放灯成对跑（"挡住 n 只·秒" = 每一帧数"有几只的目标是那盏灯"，再乘 dt）：
    `stand` 站桩（灯摆在脚下）挡住 27.5 只·秒、第一次被贴上 2.9 → 2.9 秒（**±0.0s**）；
    `flee` 直线逃（灯正好落在追兵本来就要路过的线上）52.1 只·秒、15.9 → 15.9（**±0.0s**）；
    `turn` 拐弯把它甩在身后 50.7 只·秒、14.3 → **17.5（+3.2s）**；
    `circle` 绕圈 51.5 只·秒、30.0 → 30.0（那一圈里它本来就追不上你）。

    这四个数就是这一族的全部理由：**它买到的东西完全取决于灯与追兵路线之间的夹角**——
    摆在你脚下、或者直线跑着往身后一丢（灯正好落在追兵本来就要路过的那条线上），挡住的秒数是有的，
    但"第一次被贴上"一点没晚；只有**拐个弯把它留在你不去的那个方向**，追兵才真的回头，你多出三秒多。
    换句话说：它不是盾，是一个**路标**——这一句话得自己撞一次才记得住（所以图鉴、教学卡、
    以及新加的那张"拿到这一族时的说明卡"里，讲的都是这一条，而不只是"按 E"）。
  - **灯油买得到的四个角**（一族一件，各自的数都在 `data/lamp.ts` 这一份真话里）：
    **它被啃掉的那一下**（**焚灯**，焰火：炸开一圈 34 伤害 / 半径 120，并给圈里的人点上两层灼烧。
    台架上 12/12 全中——那 12 只本来就是为了这盏灯挤到一起的。它是这一族里排最前面的一件：
    台架量出来，一盏灯在**被追着打**的时候活不到 2.5 秒，也就是说这个动词的默认结局是
    "我那一成四的油被吃掉了"；「焚灯」把那个结局改成一个**结果**）；
    **它引得到多远、站得住多久**（**灯罩**，长明：引怪半径 +40%（340 → **476px**）、多亮 4 秒（11 → 15 秒）。
    台架上同一只靶摆在离灯 420px 处——正好卡在这两个数中间：裸装时它压根不看那盏灯（一路朝你来，
    实测"朝你 1.00 / 朝灯 -0.21"），带上之后它眼里只剩那盏灯（"朝灯 1.00 / 朝你 0.11"）。
    这一件最容易写错的地方是它改的到底是哪个半径（**引怪圈**、不是亮芯），所以单测量的就是这件事；
    还有一条最容易被忽略的：**灯不能自己往追兵身上靠**——把追兵放在更远的地方（420px 外）再跑一遍，
    裸装只多买到 0.3 秒，带灯罩是 **+4.7 秒**（19.9 vs 15.2）、挡住 76.0 只·秒、追兵平均远 136px）；
    **这一族里唯一一件"省油"**（**拾灯**，灯油：它被吃掉的那一刻，正在朝它走的每一只回 0.6% 油，
    一盏最多收回它自己代价的六成。台架上引 12 只回 7.20%、引满 15 只撞上封顶 8.4%——
    "收得回来，但收不回本"是同一条规矩：它奖励的是**把一群怪聚到同一盏灯上**这个判断，
    而不是分得越勤越好（分得勤只会有更多灯被啃掉））；
    **它光里的那几只走多慢**（**灯晕**，暗影：引怪圈里移速 -30%、每帧续 0.4 秒。台架上同一盏灯同一个起点：
    裸装 68.2px/s，带灯晕 **47.6px/s**（×0.70），而"被引走"的那一份两边一模一样——
    差的只有脚力；它走的是 `applySlow` 那条共用的减速账，所以和霜印那 0.5 倍撞在一起时**不会把人家顶回快的**，
    而且裸装时它**一点都不碰**别人的减速——那只挂 0.4 秒的减速说了算：实测 54.7px/s，正好是 68 × 0.8）。
  - **它在构筑总览里有自己的一栏**（本局分了几盏、一次引走几只、收回几成油，以及四件各改了哪个数）——
    只在"分过灯、或者挂着这一族的遗物"时才画（和「伏灯」「旋灯」同一条规矩）。
    两个成就一高一低：一盏灯同时引走 8 只解「空城」（数的是**引怪圈里**有几只，吹灯客与回声不算——
    那两种有自己的目标，它们不是被灯引来的）、「焚灯」炸开那一下打到 8 只解「灯灭一击」。
  - **顺手修掉的两处"看不出来"的错**（都是这一版真的撞上的）：
    ① **图鉴的 `mechanic:lamp` 从前记在"灯被吃掉、而且圈里还有人"那一帧上**——也就是说
    分了灯但没人来吃的玩家，图鉴里永远没有这一条；而这一页正是"你已经懂了"的判据。
    现在它和伏灯 / 旋灯 / 倾灯一样，记在**分出去的那一刻**：动词只要用出来了就算用出来了。
    ② **这一族一次都没分过灯的人**（那四件在他手里就是四张废牌，和「拨芯」那四件要你先按 C 是同一个坑）
    现在会主动弹一次说明卡，而且这张卡讲的不是"按 E"，是"**摆在哪一边**"。
- **倾灯→灯潮**（v59）：到 v58 为止，灯油只是一条"捡得越多越亮"的曲线——它同时是**火力**
  （`damageScale = 0.65 + 油量 × 0.7`）、**视野**（`lightRadius = 96 + 油量 × 224`，96px 到 320px）
  与亮度，玩家从来只管捡、不管花。倾灯是第一件**花油**的武器：一瓢泼出去，落地炸开、并留下一片
  只烧敌人的火海，而它从你的灯里挖走 0.15 桶——接下来那十几秒你会明显变暗、看得见的东西变少、
  别的武器也跟着变轻。于是"灯火"从一件只能攒的东西，变成一件要决定**什么时候花**的东西。
  - **只在灯火 ≥ 72% 时才倒（`POUR.minOil`）**：它倒的永远是油桶最上面那一层，不会把玩家倒进
    "油尽"的绝境（那该是失手，不该是武器自己干的）。这一条顺手把它的射速从"冷却多短"改成了
    "你补油有多快"——**冷却对它就只是个上限**：不满时整发不出手，而且**连冷却都不走**。
    红灯区的油一次捡 4% 左右、擦身一次 0.8%、衰减每秒 1.8%，所以一瓢大致等于**四只影蛭的油**，
    或者**贴着黑暗擦十秒钟**。
  - **火海比爆炸大一圈（爆炸半径 × 1.15）**：这个 1.15 是台架量出来的——按 0.85 倍时，一片 8 只的怪
    只有 3 只落在火里，"往火上浇油"这种打法根本立不起来。自动瞄准锁的是最前那只，而一片人是从它
    往后铺开的：火得盖得住那一片，才谈得上"一片火海"。
  - **火里每 0.6 秒续一层灼烧**（走的是怪自己那套 burn，所以吃「燎原」的加成）：同一片火上多倒几瓢，
    灼烧就一层层叠上去。往自家火上再倒一瓢、而新火圈里已经站着 5 只正泡在火里的怪，就解「火上浇油」。
  - **自己倒的火不烧自己**：别的火（爆裂菇的词缀、连珠伏灯留的那层）照旧烧玩家，这一层不烧。
    因为倾灯是**自动开火**的武器——罚一件玩家没有主动按下扳机的东西不叫代价，叫冤枉；
    它的代价写在前面的油上。
  - **手动瞄准（v63 触屏 / v64 桌面）**：这一件的落点归玩家。两条路是**同一种编码**
    （方向 + 0~1 的力度，见 `InputState` 上那一段），游戏那边只认一个向量、看不出区别，
    差别只在"推了多远"由什么尺子量：手指有自己的起点（按下处就是圆心，推满 56px），
    鼠标没有起点，只能拿屏幕当行程（指针离人 0.45 个屏高算推满）。两端都落在射程的 35%~100% 之间——
    近端正好够"往自家那片火上再浇一瓢"。松开就还给自动瞄准，不按的时候这一件一点没变。
  - **四件遗物把"把油泼出去"接成一套牌**（v76，和「焰路」「爆灯」「拨芯」「燎灯」同一个做法，一族一件）：
    一件武器还不等于一种打法——单拿一件只是把这一件变好一点，四件凑起来才是
    "往人堆里倒、站在火里打、烧完的油再倒一瓢"。四个问题，一族一件：
    **那片火烧得够不够厚**（**浇油**，焰火：火每 0.6 秒续的灼烧 1 层 → 3 层。
    量的不是"被这一瓢直接砸中的那只"——满级倾灯那一下自己就带 6 层，被砸中的当场顶满，
    火再续多少也看不出差别；吃这一件的是**旁边跟着烧起来的那几只**（爆炸只给 6 层）：
    它们从起手 7 层到顶到 12 层，裸装 **5 拍 / 2.58 秒**，带浇油 **1 拍 / 0.18 秒**
    （从火烧起来算就是 6 拍 → 2 拍，而这片火只烧 4.4 秒）；
    **这一瓢铺得够不够大、烧得够不够久**（**大瓢**，长明：火海半径 **133.4px → 160.1px**，正好 ×1.20；
    多烧 1.2 秒——落地那一刻读到"还剩多久"是 3.97s → 5.17s，
    而**落点标记画的圈跟着一起变**：两处走的是同一串乘法，标记量到 160.1px 就是真火的 160.1px。
    这一条必须一致——标记的圈比真火小一点，玩家就会照着小圈站到火沿上，而「烬护」靠的正是"我到底在不在火里"）；
    **泼出去的那口油能不能回来**（**拾油**，灯油：死在你倒的那片火里的怪回 0.5% 油——一只 0.500%、四只正好 ×4.00——
    但**按瓢封顶**，一瓢最多收回它代价的六成：20 只一起死，账面 10% 被咬在 **6.12%**，而这一瓢花了 10.2%。
    见下面「已知取舍」；不带这一件一口不回，死在**别人**点的火里也不算）；
    **倒完之后那几步该走在哪儿**（**烬护**，暗影：站在**你自己倒的**那片火里受到伤害 **100 → 75**（正好 ×0.75），
    火一烧完就回到 100，而爆裂菇词缀、连珠伏灯留下的那种火一点不减——那些本来就烧你，躲进去不是掩体，是挨打）。
    三族买的是**同一桶油**的三个方向（拨芯：收着烧 · 燎灯：照着烧 · 倾灯：泼出去烧），
    所以构筑总览把它们写在**同一栏**里——摆在一起那笔账才是"我这桶油到底怎么用"，而不是三张互不相干的清单。
  - **那片火有自己的画法**：它不能跟别的地面共用"一团径向渐变"（铺满这么大一片会读成"地上放了一盏灯"）。
    所以分三层：一层不规则摊开的**油渍**（正常混合，把地面压暗——油吸光，不发光）、一片会抖的**火舌**
    （加色，按**面积**撒点，每朵的身高胖瘦由散列给，不然一眼就是"摆了一排"）、一层盖在火舌上的**柔光**
    （火苗是描出来的形状、边是硬的，罩一层雾边才化得开）。火星子按每秒十一发的节奏往上飘——
    这是这个游戏里"有东西在烧"一直在用的那句话（灯台、余烬也是它）。火舌画在**敌人之上、玩家之下**：
    一瓢落点永远是人群里，火苗本来就该从他们身上窜起来，不然最该被看见的一团火只露出一圈边；
    而玩家得始终看得见自己站在哪儿。
  满级 + 油雨 进化成**灯潮**：一瓢变三瓢，扇形泼出去，一片接着一片地烧，**还是那一瓢的价钱**。
- **燎灯→燎野（灯光本身在烧）**：到 v72 为止，玩家手里的火全都得**打出去**——枪管在哪儿、往哪儿指，
  由索敌决定；灯火只在一处变成伤害（`damageScale`：灯越亮，打出去的一切越重）。燎灯是反过来用的那一件：
  **它没有枪管**。它把"被光罩住"这件事本身当成判定，每过一小段时间往外烫一遍，罩到谁就烤谁——
  于是这一件的**射程就是你自己的灯火半径**。它是这个游戏里唯一一件**不用瞄准、也不用发射**的攻击武器，
  也是第一件"你的视野有多宽，你的手就伸多远"的东西。
  靶房量出来的数（12 只靶、满级、油钉满）：**482.7 DPS**、单只 40.2；靶子摆在 110px 还是 240px
  **读数一模一样**——它打的是"在不在光里"，不是"离多远"；330px 还打得到、340px 一颗都够不着，
  那条边就是灯火半径（满油 320px）加上靶子自己的身位。同一间靶房里的参照：追踪火苗 575、爆裂火球 1210（都是 110px 一圈）。
  - **它够不到灯外**：远程怪吊在你光圈外面放冷枪的时候，燎灯一点忙都帮不上——这正是它逼你做的那件事：
    把怪**放进来**，而不是拦在外面。
  - **拨了芯它跟着一起小，而且是这一版里被压得最惨的一件**：灯光砍一半，罩住的**面积**只剩四分之一
    （320px → 160px），再叠上 `damageScale` 那一刀 ×0.65——同一圈靶**还在光里**时读数正好掉到 **313.8**（482.7 × 0.65），
    可只要那圈靶挪到 240px，**一只都挨不到**（读数 0）。半缸油（灯火 208px）是 357.5，240px 同样挨不到。
    也就是说「遮光 / 暗火 / 夜步 / 守芯」那四件和它是**对着干**的——这是刻意的：拨芯那套买的是"摸黑走"，
    燎灯买的是"亮着烧"，一局只该选一边。
  - **它不吃范围加成**（`面积` / `广照` 那条线）：别的武器靠它变宽，燎灯的宽度写在灯火上——
    灯火自己已经有四条升级路径（油量、灯火加成、灯焰高涨、拨芯），再叠一层只会两边都说不清。
  - **它是脉冲，不是每帧扣血**：每帧扣血在画面上什么都看不见（伤害数字会刷成一片），
    而脉冲每一下都是能看见、能听见的一记"烫"。这一拍有三个可以看见的东西：
    一圈**冲击波从人身上扩出去、正好停在灯火半径上**（这个游戏里"有一圈东西散开"一直是这句话：
    燃爆、收网、点亮灯台都用它；圈停在哪儿就是它打得到哪儿，所以进化多出来的那 60px 也看得见）、
    光的边缘飞起几粒火星（不烫到人时也看得见它还在烧）、真的烫到了才响一声
    （空转不响，不然它就是一挺一直在响的机关枪）。状态上也只需要**一个**计时器，
    不用在每只怪身上挂一张会跟着怪一起长、又永远不会有人清的表。
  - **一下烫到 8 只**解「照单全收」。数的是**只数**不是伤害——伤害要乘灯火（满油 ≈ 1.35 倍、烧干 ≈ 0.65 倍），
    同一个操作能差两倍，只数才不会飘。
  - **四件遗物把"亮着烧"接成一套牌**（v75，和「焰路」「爆灯」「拨芯」同一个做法，一族一件）：
    一件武器还不等于一种打法——"光罩到谁就烤谁"听起来和"把怪放进来"没有关系，所以补上四件
    回答那四个问题的遗物：**人挤进来之后打得多重**（**旺火**，焰火：一次脉冲里每多罩住一只，
    那一下每只就多受 6%，最多 +60%——靶房实测 6 只 ×1.300、12 只 ×1.600 咬住上限）、
    **光有多大、代价是什么**（**漫光**，长明：灯火半径 +10%（满油 320 → 352px）但灯油烧快 12%
    （同样 5 秒：7.814% → 8.752%）——**它是拨芯的反面**，同一个数、两个方向）、
    **烧掉的这一口油从哪儿回来**（**吮灯**，灯油：每烫到一只回 0.05%、一次脉冲封顶 0.5%——
    15 拍实测：1 只回 0.750%、12 只回 7.500%，而**空拍一滴不给**）、
    **放进来的怪会不会把你围死**（**烟熏**，暗影：被烫到的敌人移速 -22%、慢 1.2 秒，半秒里位移
    33.92px → 26.47px；它比满级那 0.34 秒的心跳长得多，所以光里的怪**一直**是慢的）。
    四个数各归一件，凑齐才是"把怪放进来、亮着烧、烧回来的油接着烧"。构筑总览的**灯火**栏
    会把它们和拨芯那四件写在**同一栏**里——这两套是反着的，摆在一起才读得出"一局只该选一边"。
  满级 + 燎原 进化成**燎野**：一下更重、心跳更密，每一下都在敌人身上点一层火，而且**往灯外再烧出去 60px**
  （靶房上 375px 的靶照样挨打，没进化的燎灯 340px 就够不着了——那是**火**，不是光）：**2125.9 DPS**。
- **拨芯（决定这一盏灯烧多旺）**：到这一版之前，"灯火烧多旺"一直是**自动**的——油多就亮、油少就暗
  （`lightRadius = 96 + 油量 × 224`），玩家在它身上能做的只有"多杀点把油补回来"。可这个游戏的每一句话
  都在讲"灯火既是视野，也是火力"，那么"要不要把它拨小"本来就该是一个动词。
  按一下 `C`（手机上点右下角那枚「拨芯」）把灯芯拨小，四个数**同时**往下走：
  **灯火半径 ×0.5**（满油 320px → 160px：屏幕黑一大半）、**亮度 ×0.45**（火真的矮下去）、
  **火力 ×0.65**、**灯油耗率 ×0.35**——1.8%/秒 变 0.63%/秒，**一桶油从 55 秒变成 158 秒**。
  再按一下拨回来。于是"这段路暗着走、开打前烧旺"成了每秒都在做的一个小决定，而不只是配置。
  - **它的代价是"看不见"，不是"掉血"**：索敌范围就跟着灯火半径走（`findTarget` 只认灯火 +40px），
    满油 360px、拨到底 200px。台架上同一群不动的怪、同一套武器打 30 秒：贴脸（110px）那一档
    伤害掉到 **89%**（掉得比账面少，因为已经点在怪身上的**灼烧**不吃拨芯——见「已知取舍」），
    中距（240px）那一档直接掉到 **66%**：站在 240px 外的东西，不拨打得到，拨了就基本打不着。
  - **为什么是"开关"而不是"按住"**：真正用它的场面是"赶路那十几秒"——左手已经在 WASD 上了，
    再让它压住一个键是给操作添堵；而且它要表达的状态本来就是"这一段路我打算暗着走"，
    一个能自己站住的开关比一根要一直摁着的键更贴这件事本身。手机上同理：一次轻点，手就回来了。
  - **速度是不对称的**：拨小 0.28 秒（危险来了先隐下去再说）、拨回来 0.42 秒（重新烧旺本来就要几秒）。
    和冲刺 / 燃爆的"按下缓冲"同一个道理：该快的那一下不能欠着。两个值之间的插值让火是**矮下去**的，
    不是"啪"地换一张画面。
  - **它会和别的东西咬在一起**：夜枭 / 低油增伤那类"越暗越狠"的构筑天然合拍（把油压在低位、又不熄灯）；
    倾灯 / 燃爆 / 分灯照旧按油算账（拨着芯不代表那些动词变便宜）；地里的伏灯、地上的弃灯**不跟着变暗**
    （它们是另外几盏灯，拨的是你自己这根芯）；而「灯焰高涨」正好是它的反面——一个要你把火烧旺，
    一个要你把它压住。**灼烧也不吃它**：已经点在怪身上的火照旧烧，所以火焰流（烈焰鞭 / 倾灯）
    拨芯时亏得最少。
  - **地板**：灯火半径有个 72px 的下限。油快烧完时再拨一半会掉到 50px 以下——那不是取舍，是把玩家变瞎；
    "脚下这一圈永远看得见"，其余的部分才是你自己拨掉的。构筑总览里单开一栏**灯火**：
    半径 / 亮度 / 火力并排写出来，拨着芯时那一栏会冷下来。
  - **四件遗物把"暗着走"接成一套牌**（v70，和「焰路」同一个做法）：一个动词还不是打法——
    "拨着芯"本来只适合赶路那十几秒，一开打就得拨回来。所以补上四件**一族一件**的遗物，
    回答暗着打最要紧的四个问题：**会不会被打死**（**遮光**，暗影：拨着芯时受到伤害 -25%）、
    **靠什么输出**（**暗火**，焰火：拨着芯时每次命中添一层灼烧——火不在这盏灯里，所以拨芯拨不到它）、
    **怎么走**（**夜步**，长明：拨着芯时移速 +12%）、**省的油去了哪、能不能更省**（**守芯**，灯油：
    拨着芯时每秒回 0.3%，和油壶那种"乘出来的省"是两笔账，凑起来油面几乎不动）。
    四件都只在 `player.dimmed`（插值过半）时生效，数值都不大：它们买的是"另一种活法"，不是纯战力——
    单拿一件只是把赶路那一段变好一点，四件凑起来才是"把油压在低位、灯火压到最小，
    靠灼烧和身法在黑暗里打"。它和「灯焰高涨」正好是一个反着的方向。
    构筑总览的**灯火**栏会把身上那几件写出来（拿到哪件写哪件）。
- **14 件武器 + 14 种进化**：火环→日冕、火苗→群萤、火球→陨火、火鞭→龙息、光刃→破晓长枪、喷射→焚风、
  **雷弧→千雷**（连锁闪电沿敌群跳跃）、**霜棱→永冻冰川**（减速寒霜）、
  **光矛→晨光破晓**（一条贯穿直线，把排成一列的敌人串起来；进化后带灼烧）、
  **回旋灯刃→双月轮**（掷出去再飞回来，去程与回程各能打一次；进化后三枚同时旋出）、
  **伏灯→连珠伏灯**（撒在身后的雷，见上）、
  **旋灯→漩涡灯**（把一群人拢到一点，见上；它是第一件"给别人打下手"的武器）、
  **倾灯→灯潮**（花自己的灯油泼出一片只烧敌人的火海，见上；它是第一件能"花"灯火的武器）、
  **燎灯→燎野**（灯光本身就是武器：光罩到哪儿就烤到哪儿，见上；它是唯一一件不用瞄准、也不用发射的）。
  满级武器 + 对应满级被动即可进化。
  - **"新武器"这一档的候选表是从武器表现取的（v73 修）**：它以前是一份**手抄**的 id 清单，
    而 v62 加旋灯、v73 加燎灯的时候两次都没往里补一笔——两件武器数据齐全、图鉴有词条、成就挂着、
    体检脚本也在跑，**可玩家一局都抽不到它**。一件进不了升级池的武器等于不存在，偏偏这种漏法
    **不报任何错**，它只是安静地少一个选项。现在候选表由武器表派生（非进化 + 去掉开局那六件），
    并且有两道人工对账：`tests/data.test.mjs` 逐个比对"一件都不能少、进化的一个都不能有"，
    `tests/aura.test.mjs` 那条用例真的去抽**三百次**升级面板——把"抽不到"变成一条会红的断言。
- **24 项升级**：14 个被动（伤害/攻速/范围/暴击/回复/灯油……）配合武器等级构成每一局的构筑。
- **68 件遗物与商店**：精英与 Boss 掉落遗物，关卡间隙进入商店用金币换取遗物 / 回血 / 重掷。
  分成两类：纯增益（磨石、油壶、不死羽……）与**契约型**——更强但带代价（双芯多一发但更慢、
  猎人之眼暴击换血上限、静默石省油但变慢、苦修之环高伤高耗油、玻璃心高伤但脆、焚心高伤但吸不到东西）。
  还有几件改变打法的核心遗物：**夜枭**（灯油低于 35% 时伤害 +45%，逼你把灯火压到危险线）、
  **守灯人**（燃爆后 3 秒内伤害 +25% 并返还灯油，把燃爆变成输出节奏的一部分），
  以及**守夜灯**——它把上面那条「灯台」的线接进构筑里：每座灯台的余温翻倍、灯焰被吹灭的速度 -45%，
  于是"这一局的灯值不值得一座座点过去、守下来"，取决于你带了什么。
  「焰路」那四件（**焰心**/**长风**/**撩芯**/**影缝**）走的是同一条路：它们把「掠影」接进构筑，
  而且正好一族一件（焰火 / 长明 / 灯油 / 暗影各补一件），凑共鸣和走打法第一次变成同一个决定。
  店里还多了一台**熔铸台**：花金币把一件已有遗物烧掉换成另一件（同稀有度优先），
  每家店限一次——契约型遗物的代价终于有了出口，"忍下去"和"花金币换掉"变成一次真实的决定。
- **灯火共鸣（遗物套组）**：68 件遗物按脾性分成四族（每族 17 件）——**焰火**（伤害与暴击）、**长明**（范围、冷却与续航）、
  **灯油**（灯油与金币）、**暗影**（血量、吸血与减缓）。同族凑够 **3 件**解锁第一档、**5 件**再解锁第二档，
  两档叠加。于是"下一件买什么"不再只是比数值，而是要不要把手里这套凑成一个体系；
  凑齐的一族会报一声、在 HUD 的构筑行上挂一枚小芯片，构筑总览里也写清每一族还差几件。
- **灯台（探索目标）**：每关在远处散着 3 座熄灭的石灯（终局的长夜之城有 4 座）。站在旁边停留约 1 秒
  就会点燃——离开则进度回落。点燃换来三样东西：**一处长明**（那一片从此一直亮着，是可以退守的据点）、
  **本局余温**（灯光半径 +6%、伤害 +5%，可叠加）、一点金币与灯油；代价是点燃的动静会把附近的东西叫过来，
  其中就包括**吹灯客**——它不追你，绕过去直奔灯台，把灯焰一点点抽干（地上你埋的伏灯它照吹不误）；灯焰归零，这座灯台重新熄灭，
  余温也跟着原路收回（灯焰剩多少，火就小多少，一眼看得出哪座快守不住了）。
  于是"要不要在一片黑暗里停下来"变成一个真实的取舍，而点亮之后还得守。没点亮的灯台会在黑暗里透出一小团余烬微光，
  出屏之后退化成屏幕边缘的一枚箭头（灯台 / 祭坛各一种颜色，最多显示最近的三个），
  既不让你迷路，也不把路直接给你。
- **祭坛（风险抉择）**：每关随机生成 2 座蓝色祭坛，靠近后从三张卡牌中三选一或原样离开——
  血契（生命上限 -20% 换随机遗物）、燃薪（伤害 +12%、耗油 +18%）、献金（立刻 +60 金币但收益 -10%）、
  守夜（回满血油但惊动黑暗）、节食（耗油 -25%、生命上限 -10%）。抉择永久影响本局。
- **连杀奖励**：连续击杀累积连杀槽，达 6 / 15 / 30 / 50 触发四档奖励，额外金币与专属提示。
- **夜咒（每关自己挑一条）**：第二关起，每离开一次补给站会先停在**夜咒岔口**——三条候选，挑一条带走。
  群潮（敌人 +30%）、铁衣（生命 +35%）、
  血怒（伤害 +30%）、深潜（黑暗更浓 + 开局补油）、长夜（本关波次 +2）、盛宴（数量与生命同时提升）、
  夜曲（黑暗更浓且敌人更多）、**低语**（所有敌人持续回血，拖久了会白打）、
  **枯灯**（灯火衰减 +55%，把资源压力直接顶到脸上）。
  夜咒一律附带金币回报（+30% ~ +70%），候选会按回报从轻到重排，"要钱还是要命"一眼看得出来；
  挑中的那条 HUD 顶部常驻显示。夜咒不会缺席（总得挑一条），但**挑哪条是你的决定**——
  今日灯芯的夜咒由日期定死，不参与挑选，这样大家的夜晚才是同一个。
- **精英词缀**：迅捷（移速 +50%）、铁壁（生命 +70% 并减伤 30%）、分裂（死亡时分裂）、
  燃烬（死亡时炸开火焰）、巨化（体型与生命提升但更迟缓）、再生（持续回血）、剧毒（死亡留下毒地）、
  **咒盾**（免疫灼烧与冰缓并额外减伤，专门针对元素流）、**疾风**（光环：附近敌人 +35% 移速）、
  **蚀油**（光环：站在附近会一直掉灯油）、**噬魂**（死亡时把附近同伴喂饱）、
  **荆棘**（接触伤害 +50% 并额外抽走灯油）。
- **13 种敌人 + 3 精英 + 4 Boss**：影蛭、砾行者、喷糜者、灯蛾、石守、蚀烛（偷油）、爆裂菇（自爆）、
  **疾影**（极脆极快、突进冷却很短的残影）、
  **碎魂**（五面晶体，死亡时炸成两只影蛭）、**刺脊**（蓄力后沿着预警线高速突进，必须靠闪避处理）、
  **引灯**（提灯亡灵，为周围敌人提供速度光环并照亮四方，优先击杀可以立刻削弱整片敌群）、
  **回响**（不追你，追你一秒前站的地方——直线逃跑会被它从背后咬住，走折线才能甩开）、
  **织雾者**（边走边在脚下织出滞行雾，雾里脚步会沉下去，要么绕开要么先点掉它）；

- **分灯（E）**：把一小罐灯油点在地上——它照亮一小圈，并把附近的黑暗**引过去**。
  这不是一个免费的控制技，而是一次取舍：油就是光、光就是命，所以你分出去的是自己的亮。
  亮芯之外还有一大圈很淡的"饵光"，**亮着的地方就是会被引过去的地方**（同一条规则，不用再解释）。
  它也不是万能：凑上来的怪会把这盏灯**吃掉**（人越多灭得越快，一群扑上来只能顶一两秒），
  吹灯客更是飞过去一口气就吹灭。冷却 7 秒、要两成油起，一局能放几次是要算着用的。

  所以 v83 照老规矩给它补了一族四件（见下面「弃灯」那一段）。
- **四种燃爆流派**：同一个「燃爆」在四位灯火手里完全不同——守夜人推开全场并回血、
  灯语者照亮四野点燃全区域并返还灯油、焚烬者半径与伤害暴涨且附带灼烧、暗行者以黑暗为刃
  大范围减速并在短暂无敌中抽身。选哪个灯火，等于选一种清场方式。
- **4 个主题关卡**：幽林 → 残堡 → 熔窟 → 长夜之城，程序化生成竞技场并铺满主题布景（树木/蘑菇、立柱/瓦砾、
  晶簇/熔岩裂隙、蚀月立柱/铜炉/骸骨），含关卡事件（陨石雨、塌方、熔岩喷发、浓雾、相位风暴、灯油抽取、
  回声涌来、**荆棘回廊**、**寒潮**、**余烬风**）。其中两种险境把压力放在"位置"上而不是"血量"上：
  **荆棘回廊**在四周围一圈带缺口的荆棘，逼你在一秒半里找到那道缝；
  **寒潮**铺下几片霜冻，踩进去会又慢又费油、灯火也暗一截——它不咬人，但你会知道自己是站在哪儿挨打的。
  **余烬风（v65）**是第三种：它不咬血，咬**油**。一阵风把烧着的余烬从一侧推过战场，
  沾上身就粘住（最多三层），每层每秒烧掉 1.6% 灯油——而油见底本来就是这一局的死法，所以它咬的是命根子。
  火种永远比走路**慢一点**（0.75 → 0.95 倍脚力，越吹越急），于是三条路各有各的价：
  顺着风跑一层都沾不上、横着走也不挨打、**迎着风走就是自己撞进火里**（实测一整阵风跑完：
  顺风 0 层 / 终油 0.92，站着不动顶满三层 / 0.68，逆风也顶满三层 / 0.59）。
  解有两个，一个是手、一个是脚：**冲刺**一下当场把身上的火抖掉（按的又是那个只管躲的键，
  两个用处在同一条冷却上抢）；或者**跑向一盏亮着的灯台**——长明的光把火种按灭，
  站在它旁边每秒掉一层（v66）。后一条不是"更快的解"，是"另一种解"：
  灯台离出生点 620px 起、彼此隔 760px，跑过去要时间，但花的是**位置**不是冷却。
  它只出现在熔窟（焚天的巢穴），一个八秒的风里全程硬吃是 38% 的油，吃得起但得还。
  终点是「终夜」盘踞的长夜之城——难度与节奏都顶到最高，也是通关成就的最后一块拼图。
- **无尽之夜**：单场无尽波次，每 5 波一轮、每轮一位首领，四只首领轮番登场并逐轮变强，排名看最高波数。
  没有分母的进度条改写成"离下一轮首领还有几波"，首领前一波照样预告；
  **第 3 轮起两位首领一同上场、第 5 轮起三位同台**——单只首领的招式背熟之后才轮到新题。
  同台越多，各自压得越低（0.9 → 0.62 → 0.46），不然三份满血叠在一起只是把时间拉长；
  HUD 的血条也跟着一列排下来，每位首领一行名字 + 一条血，谁快倒下了一眼看得见。
  **一轮一片战场**：无尽从「幽林」开始，每打完一轮（结算点是补给站）战场就换一片——
  主题、布景、险境池、精英池、灯台与祭坛全部重铺，走完幽林 → 残堡 → 熔窟 → 长夜之城再回到幽林，
  同一片战场第二次进来是新铺的一局（种子带着轮次），不是上次那张图。
  换场只在补给站里发生（不会打到一半把场地抽走），而且**不送血也不送油**——那一口补给得在补给站里买；
  难度与物价档位也不跟着战场走：`stageIndex` 一直钉在最后一关，不然第 5 轮回到幽林时物价会突然便宜下来。
  补给站里提前写着「下一片战场 · 熔窟 · 险境：熔岩喷发 / 陨石雨」——身上没血没油的时候，
  看到下一片是熔窟和看到下一片是幽林，要买的东西是不一样的。
- **今日灯芯（每日挑战）**：同一天里所有人面对**同一个夜晚**——灯火、难度、每一关的夜咒与悬赏
  全部由日期推导（纯函数，不看运气），随机种子也来自日期，于是成绩之间才有比较的意义。
  面板里能看到今天的全部条件与个人最好成绩，局内依旧是随机应变的（固定的是条件，不是过程）。
  成绩按"推进"计分（击杀 2 分、每关 120 分、通关额外 400 分），跨天自动重置。
- **局外成长（16 个节点的解锁树）**：每局结算获得「余烬」，在解锁树里永久解锁新灯火与开局增益——
  生命、灯油、余烬收益、冲刺、重掷、起始武器等级、开局被动、复活，外加四种改变开局的节点：
  **钱袋**（开局金币 +40）、**暗视**（起始灯火半径 +12%）、**夜行**（起始移速 +7%）、
  **旧灯**（开局随机获得 1 件遗物，运气好能直接点亮一族灯火共鸣）。节点带前置，越深越贵。
- **薪火（v80）——余烬的第二个出口**：树是**一次性**的（16 个节点一共 2560 余烬），而余烬是**一直在挣**的。
  台架量过：脚本玩家自然死在第 1 关约 150 余烬，一趟真打通（4 关 / 13 分钟）约 **3200**——
  也就是说**一趟通关就能把整棵树买完**。树买完之后那个数就再没有出口了，而 v79 的「深宵之约」
  还把它乘得更大（七条全背 ×2.05）。所以树底下补的是一口**炉子**，不是第二棵树：
  三条梯子各六级、改成一份**起手的底子**——**薪柴**（火力 +4%/级，满 6 级 +24%）·
  **亮芯**（灯火半径 +3%/级，满级 +18%）· **油瓮**（起始灯油容量 +5%/级，满级 +30%）。
  三条合起来正好 18 级、**19170 余烬**（按上面那个读数约六趟通关），每一级比上一级贵 **45%**，
  于是每一级都是一个当晚做得完的决定，而"一条线的最后一级"单独就等于大半趟通关。
  三条设计规矩：**它比树贵得多、而且这是有意的**（树是买卖：60 余烬换 +18% 油；炉子是去处：
  320 换 +5%——单位余烬差着一个数量级，面板上还写着"解锁树还剩 N 个节点"指路，
  免得新手先来烧炉子把钱花错）；**价格本身是阶梯**（不是"越买越便宜"，也不是"贵到买不起"）；
  **封顶**（18 级之后这个系统就结束了——不封顶的话它就成了"比谁攒得久"，难度那几条线全部失效）。
  烧满一条解「添到顶」、三条全满解「长夜不熄」；它是元进度里**第一次**动火力的一条线，
  走的是和「夜行」同一个位置（`Player.metaMods`），所以拿到遗物重算一身属性也不会把它冲掉。
- **构筑总览**：`Tab`（或暂停面板）随时翻看当前这一局的全部筹码——武器与等级、遗物、
  被动层数、本关夜咒、当前悬赏、以及伤害倍率 / 冷却 / 暴击 / 移速 / 灯油耗率等关键属性。
  **进化路线**直接写出"离进化还差什么"（武器 3/5 · 长明 2/5），条件齐了会高亮；
  升级三选一里若某张卡能推动进化，卡面会提前提醒。肉鸽的乐趣在于"我这套牌到底成了什么样"，
  所以它一直在手边——而"下一张该拿什么"也不该靠猜。
- **升级卡写清"这一级改了什么"**：卡上除了名字与简介，还有一排**等级刻度**（亮着的＝已经拿到几级，
  在呼吸的那一格＝这张卡要点亮的那一格）与一行**数值对照**（`伤害 42 → 52`、`暴击率 6% → 34%`、
  `灯油耗 ×0.88 → ×0.77`）。同一把武器的第 3 级和第 4 级名字一样、图标一样，差的只有数——
  这张卡就是拿来比数的。数值是**预览**算出来的：把"某件被动再多一级"整套属性重算一遍，
  不落到玩家身上（不然没点的卡会先加上属性，还会把血条顶过上限）。
  进化卡只写"变强"的那两项（伤害 / 间隔）：进化是换一种打法，进阶武器少一两发是设计，
  把"数量 5 → 4"当成缩水印上去只会误导。商店里能买到武器 / 被动的那几格也一样——
  那笔金币到底买到了什么，在掏钱之前就看得到。
- **三档难度**：放松 / 标准 / 噩梦，影响敌人数量、伤害与资源掉落。
  难度给灯油的那一档倍率（**放松 1.35 / 标准 1 / 噩梦 0.75**）乘在**玩的时候一直在发生的那三条进项**上：
  击杀掉落、擦身回油、灯台余温——三条都算，因为它们是同一件事（我靠本事补的油）。
  这一条是 v65 修的：原来它只乘掉落，而放松那一档的**敌人本来就更少**（`countMult` 1.1 对标准 1.35），
  于是越弱的档位反而越缺油——面板上那句"灯油充足"是反着写的。
  一次性的结算（悬赏奖励、开局补给、夜咒补油）不乘它：那些不是"进项"，是一次给的。
- **「深宵之约」——自己给自己加的难度（v79）**：通关一次之后，选灯火那一屏多出一排七条，
  想背几条就勾几条；每一条 **+15% 结算余烬**，乘在难度那一档与局外那个数**同一个位置**上，
  于是七条全背是 **×2.05**（四条正好 ×1.6）。为什么还要这一套：三档难度之间**只差倍数**，
  "噩梦"打熟了就是"同一张题做久一点"，它不逼你换打法；而这一套是**规则**，每一条只改一件事，
  改的全是每一局、每一波都在发生的事——**来客更密**（每波数量 ×1.25，实测第三波预算 18 → 22）·
  **壳更硬**（同种怪血量 ×1.3）· **爪更利**（伤害 ×1.25）· **灯烧得快**（灯油自然衰减 ×1.4，
  烧 10 秒实测一桶走掉 15.84% → 22.18%）· **昏灯**（灯火半径 ×0.88）·
  **薄油**（掉落 / 擦身 / 灯台这三条进项 ×0.75，一次掉落 100 → 75）·
  **成群**（每关那一次精英波多来一位，1 → 2 只）。三条设计规矩（写在 `src/data/pacts.ts` 顶上，
  因为它们决定了每个数为什么是那个数）：**每一条都一直在咬**（不收"只在某种构筑下才生效"的条款——
  那种条款对另一部分玩家等于没加，和"拨芯那四件在没有拨芯的人手里是废牌"是同一个坑，
  所以这里没有"禁用复燃""不能重掷"这类只在有那个元进度时才有意义的条款）；
  **每条一个数、而且改得出形状**（六条是最小气的"再多一点"，最后一条改的是**节奏**，不只是"数值更大"）；
  **每条一样贵**（回报不按"这条有多难"分别定价——那需要一张站不住的难度权重表；这一套要回答的问题
  只有一个："这一局你想背几条、你敢背几条"）。今日灯芯**不吃**这一套（那一天所有人共用同一道题，
  谁能背几条等于谁的成绩不成立）；钥匙直接读生涯档案里那个"通关次数"（通关一次就开，
  不另存一个开关——多一个开关就多一条"它和那个数哪个才算数"的第二种真话，而且老存档不用重打一遍），
  锁着的时候那一排不是灰按钮，而是一行字写清怎么开。
- **关卡进度看得见**：HUD 的波次写成 `3/10`，关卡名下面一条细进度条填到第几波、
  末尾一段用红色标出首领波；首领前的那一波会明确预告"首领将至"——
  玩家该知道还剩几波，而不是靠数着等一个突然站在脸上的首领。
- **图鉴（编年史）**：175 个条目——21 种敌人（含精英与首领的应对说明）、28 件武器与进化、
  68 件遗物（分属 4 个共鸣之族）、14 个被动、9 种夜咒、12 种精英词缀、4 位灯火、**10 种险境**、4 张关卡，
  外加一章**机制**（掠影、灯焰高涨、伏灯、旋灯、倾灯、燎灯、**拨芯**、**循灯**、**深宵之约**各一条：带子多宽、几秒记一次、攒满要多少、焰给多少又拿走多少，
  以及雷上弦几秒、管多大一片、地上最多几颗、连爆的引信几秒、它还算不算一盏灯，
  还有旋灯落在哪、吸多久、拽得多狠（含那道垫起来的外沿）、拽不动谁、收尾怎么算账、
  收网的门槛是什么、收尾为什么不击退、
  还有专为它准备的那四件遗物（数值直接从 `data/vortex.ts` 与 `data/relics.ts` 现取），
  以及倾灯什么时候响（那道灯火门槛）、一瓢多少钱、火留多久、烧得到自己吗、和谁抢油，
  以及燎灯的射程怎么等于灯火半径、多久烫一下、一下多重、灯外为什么一点都够不着、
  它和「拨芯」为什么是对着干的、进化的那 60px 烧出去的是什么（数值直接从 `data/aura.ts`
  与 `data/weapons.ts` 现取），
  以及拨芯的四个乘数、两个时长，还有专为它准备的那四件遗物（数值直接从 `data/wick.ts`
  与 `data/relics.ts` 现取）；
  循灯什么时候开始、那几只改做什么、跑多快、首领算不算，
  以及深宵之约那七条各改了哪个数、锁着的时候怎么开、背几条余烬翻几倍——每个机制各占一条，
  遇上了才记进来，数是从 `src/data/*.ts` 现取的，改调参图鉴会跟着变）。
  一切"被玩家看见过"的东西都会被记录，没见过的显示为问号；**点开已发现的条目能查数值**——
  敌人的生命 / 伤害 / 经验 / 行为、武器的伤害曲线与进化条件、夜咒的具体倍率、关卡的首领与险境。
  险境单独成一章（遇上才算发现）：每条先写"它长什么样"，再写"怎么应付"与"出现在哪些关"——
  以前险境只在关卡条目里一笔带过，而它本来就是每十几秒发生一次的事。
  填满图鉴另有两项收集成就。
- **悬赏（每关一张）**：每关开局随机贴一张小目标——猎杀契约（本关清掉 N 只指定敌人）、
  烽火（连杀堆到 15 / 25）、燃爆（本关放 3 / 5 次）、静默（连续 45 / 75 秒不受伤）、
  点灯（本关点亮 3 座灯台 / 把本关灯台全部点明）、掠影（本关擦身 30 次 / 点着 2 次「灯焰高涨」）。
  奖励一律是金币与补给而非余烬：金币只在局内花得掉，等于把出价换成"下一关更强"。
  HUD 左侧常驻任务追踪，构筑总览里也能翻到。悬赏池会随关卡深度放开——
  第一关不会让你去打还没出场的敌人，也不会派给你还没见过的机制（掠影那两张从第二关起才进池）。
- **结算把这一局讲完**：死亡时先交代**你是怎么没的**——"灯火熄灭于 焚天"，接触伤害、敌人弹幕、
  陨石雨、毒地、荆棘各说各的名字，而不是只丢一句"你死了"；再把本局高光摊开：击杀、存活、
  最高连击、造成 / 承受伤害、击败首领、**点亮的灯台**、**布下的伏灯**
  （连爆过还会多写一行"最长一串 n 颗"，被吹灯客吹灭过就写一行"被吹灭 n 颗"）、完成的悬赏、最强一击与燃爆次数。
  通关则换成一句"沿途点亮了 n 座灯台"——它本来就不是必做项，所以值得被记下来。
  **本局伤害构成**单列一块：这一局的枪法是自动的，玩家一直在做的决定只有"升级给谁"，
  而结算从前只给了**一个**总伤害——哪件在扛、哪件在刮，只能靠感觉猜，于是"下一步堆什么"这个
  肉鸽真正的乐趣就被藏了半个。现在每一件出过力的武器各占一行：名字、按占比画的条、伤害数与占比，
  按伤害从多到少排；不挂在武器上的那几条来源（燃爆 / 灯火 / 灼烧 / 其他）也各有名字，
  免得它们被悄悄搅进某一栏里。这张表**只在两件以上来源时才出现**——手里只有一把武器时，
  它说到底就是"100% 是它"，占地方而已。为了让这张表诚实，账只在**一个地方**记
  （`Game.creditDamage`）：每一次伤害都走那一条路，于是"各来源之和 === 造成伤害"是一条**恒等式**，
  不是四舍五入到看着像——这条恒等式被软件测试与真实浏览器各钉了一遍。
  顺带把口径摆正了：从前"造成伤害"漏掉了灼烧那部分，现在补上了（生涯档案里的"单局伤害"也跟着更准）。
  最后再把**这一局长成了什么样**摊开：点满了哪几把武器、拿了哪些被动与遗物、凑齐了哪一族的灯火共鸣、
  背着哪条夜咒走完的——肉鸽真正被记住的是构筑，而不是那串击杀数。
- **首局引导**：第一次开局会依次提示"自动开火 / 空格冲刺 / Q 燃爆""灯台可以点亮""祭坛与商店在哪"，
  以及一张**分灯**的说明卡（放在开局 14 秒后，避开刚进战场那两秒的乱），
  放完一次就写进存档，之后不再打扰；第二局起只留 HUD 底部那行常驻说明。
- **首次遭遇提示**：第一次撞上某个**精英 / 首领 / 险境**（以及第一次点灯招来「吹灯客」）时会弹一张小卡，写清"它是什么、该怎么应付"，
  只弹一次。精英按"敌人 + 词缀"去重——所以「咒盾烛母」讲过的打法，换成别的词缀会再讲一遍，
  因为打法完全不同。这份文案就是图鉴里的 `note`，图鉴与实战提示共用一份说明，玩家不必两处维护记忆。
  同样地，**第一次拿到某把武器**（升级面板或商店里买到）、**第一次完成一次进化**，以及
  **第一次走进某一关**（主题、险境、首领一次讲完）也各弹一张卡：二十把武器靠图鉴自己翻太慢，
  而刚上手一把武器、刚踏进一关，正是一个人最愿意读说明的时候。
- **生涯档案**：结算时把每一局沉淀下来——个人纪录（最高连杀 / 单局击杀 / 单局伤害 / 最快通关……
  与结算界面的「🏅 新纪录」徽章联动）、四盏灯火各自的战绩对比，以及最近 12 局的战报列表。
- **55 项成就 / 统计 / 本地存档**：成就解锁时额外发放余烬（共 3540 点），直接喂给局外解锁树。
  成就面板按「战斗 / 关卡与首领 / 抉择与风险 / 收集与档案」分组，并在每组标题上写出进度（`7/17` 这样的形式），
  于是"下一步该冲什么"不用逐条扫；新内容也各有对应成就——一次光矛贯穿 5 个敌人、回旋灯刃回程命中、
  在滞行雾里泡满 20 秒、一颗「伏灯」同时炸到 5 个敌人、一次连爆把 4 颗伏灯串成一条线、
  一颗伏灯一次炸到 4 只灯蛾、一个「旋灯」里同时拽住 6 只敌人、一次收网打到 10 只、

## 画面与手感

- **按下的那一下不会被丢掉（v65，v66 画出来了）**：`冲刺`与`燃爆`各有一小段**按下缓冲**（0.2 / 0.15 秒）。
  触屏按钮上这件事是看得见的：冷却还在转、但这一下已经被记下了，按钮的边光会转成琥珀色（`is-buffered`）——
  不然玩家看到的永远只是"按了没反应"，而缓冲本来就活在代码里（真机实测：冷却只剩 0.13 秒时按下，
  按钮亮起、转完自己放出那一发）。
  冷却还差一点点时按下的那一次，先替他记着，冷却一转完立刻放出去。
  这是拿离线台架量出来的：机器人在怪贴身时一秒按几十次冲刺，其中 **97% 以上**落在冷却里被直接吃掉
  （脚本整局按了 1018 次、992 次什么都没发生）——玩家看到的是"我按了，人没动"。
  这不是难度，是把操作丢了；尤其在"贴脸了必须立刻走"的那一瞬，玩家按下的时机本来就只差那么一点。
  两个窗口不一样长也是刻意的：冲刺是位移，记久一点没关系；燃爆要花掉一桶油里的一大块，
  记太长就成了"我早就不想放了，它自己放出去"——那比没按上更糟。
  窗口跟着 `dt` 走（按秒算），所以掉帧和 120Hz 上是同一段真实时间；
  边界也钉死在测试里：窗口**外**按下的那一下绝不能攒到冷却结束时才放（那是延迟施法，比没反应更糟）。
- **灯火即画面**：光照贴图每帧重绘——黑暗是一层叠加的夜色，光照是在夜色上「挖出来的洞」，
  再叠一道加法暖光与泛光 Bloom，灯焰周围因此自然形成一圈暖色高光。光照半径内还漂浮着
  缓慢上升的**微尘**，让「光」看起来有体积；屏幕叠加**暖色分级 + 冷色暗角**（暗角用乘算偏靛蓝
  而不是简单套黑框），亮部偏暖、暗部偏冷。
- **地形细节**：每关把主题纹理烘焙成平铺位图，再撒约 400 个细碎装饰（草丛 / 石子 / 蘑菇 / 裂纹 / 余烬），
  光照范围内看得见真正的地面而不是色块；墙体带顶面受光带、暗面与深色轮廓。
- **地上那片火是"画"出来的，不是"发光"出来的**：别的地面效果（毒地、霜冻、着火的雷区）都是一团
  径向渐变的加色光晕，铺满一大片就会读成"地上放了一盏灯"。倾灯倒出来的那片油火另有一套：
  先摊一层不规则、把地面压暗的**油渍**（油吸光，不发光），再撒一把高矮胖瘦都由散列决定的**火舌**
  （按面积铺点——撒在半径上的话，火会自己排成一圈、中间留个洞），最后罩一层**柔光**把描出来的硬边化开，
  外加每秒十一点往上飘的**火星**。实测 6 片同时烧的帧时间与一片不烧相差不到 1ms。
- **角色剪影**：守夜人有兜帽、肩线与随移动飘动的披风拖尾、冲刺残影，提灯朝向瞄准方向形成光锥。
- **首领演出**：脚下旋转光环 + 深色轮廓把首领从泛光里「切」出来；登场与死亡伴随闪白、故障切片、
  慢镜与屏震。
- **菜单海报**：主菜单不再是黑屏，而是会动的海报——星空与冷月、天光、层叠剪影山、缓慢横移的雾带、
  上升火星，和中央的持灯守夜人。
- **UI 材质语言**：界面不共用一套"深色圆角面板"，而是**按东西的材质分族**——操作台是**锻铁 + 四角黄铜件**、
  记录是**皮纸账本**（虚线格 + 左缘装订针脚）、解锁树与设置是**黄铜仪表盘**（刻度 + 凹槽导轨 + 铜滑杆）、
  祭坛是**冷石**（四角凝霜）、夜咒是**蜡封**（压印在面板角上的封蜡）、主菜单是**钉在夜色里的铁招牌**。
  主行动键是"浇出来的黄铜"（竖向拉丝 + 暗色下沿），次级键是熟铁键（暖灰，不用冷蓝），
  键帽、滑杆、价签、价格牌都是黄铜；HUD 当成一只铜仪表：四角框角、灯芯状进度条（会随燃烧微微闪烁）、
  斜口铁标签、铜牌计数。
- **主菜单的层级**：同质化最容易发生在主菜单——八件事如果都画成一样大的圆角方块，
  信息再多也只剩"一种东西"。所以这一屏按**要做的事 / 要翻的账**分成两列：左列是立刻要做的
  （一块黄铜牌的主行动，底下一行写清这趟走到哪；再并排两张铁牌的无尽之夜 / 今日灯芯），
  右列是余烬解锁 / 图鉴 / 生涯档案 / 成就 / 设置压成的一列薄账目（左侧黄铜刻痕、右侧等宽黄铜数字、
  行间发丝细线，"设置"没有数字可数就压回暗色小字）。招牌的底色是冷锻铁，只有顶上一盏灯影是暖的，
  于是"暖"重新变成信息。两列并排还顺手把横屏矮屏的纵向空间省出来——844×390 上生涯摘要那一行
  原来塞不下要藏掉，现在是两列并排、页脚放得下。
- **UI 字体分层**：标题、段落小标题、账目数字与关卡名用**衬线**（`Noto Serif CJK SC`，缺字体时落到系统宋体），
  正文 / 按钮 / 说明保持无衬线——所以结算页读起来像一本账，按钮读起来仍然清楚。

## 无头渲染自检（沙箱友好）

没有浏览器也能"看一眼"游戏画面：`tools/softcanvas.mjs` 是一个纯 JS 的软件光栅化 Canvas2D
（路径填充/描边、渐变、图案、`drawImage`、混合模式、超采样），`tools/render.mjs` 用它引导真实的
`dist/app.js`，模拟指定场景若干帧后渲染成 PNG：

```bash
npm run build
node tools/render.mjs --scene play --ss 2           # -> /tmp/wl/play.png
node tools/bench-waves.mjs --seeds=6                  # 波次节奏：刷怪 / 清场 / 尾巴 / 空场（再拆成刷怪阶段·清场阶段）各占几秒
node tools/bench-waves.mjs --fixed --seeds=6           # 钉死火力（同一套武器、不升级、不开商店）：改规则前后 A/B 用这个
node tools/bench-waves.mjs --god --stages=4            # 打不死的脚本玩家跑完四关：跨关卡找崩溃用（8 颗种子 328 波不崩）
node tools/bench-weapons.mjs --weapon=aura --secs=30   # 单件武器台架：一间靶房，12 只打不死的靶摆在同一圈，量这一件自己打得出多少
node tools/bench-weapons.mjs --weapon=mine --walk=sweep --secs=60   # 让玩家自己跑起来（circle|sweep|zigzag|straight）：伏灯那类"看你怎么走"的账
node tools/bench-weapons.mjs --weapon=aura --wick --oil=0.5         # 拨着芯 / 半缸油：灯火既是射程又是火力的那条曲线
node tools/bench-lamp.mjs --relic=lamphaze                            # 分灯台架：四种走位、放灯 / 不放灯成对跑，量这盏灯替你挡住了什么
node tools/render.mjs --scene boss1 --crop 560,240,260,180 --zoom 4
```

可用场景：`menu play swarm boss1 boss2 boss3 boss4 elite bomber stage3 stage4 shrine pyres snuffer splinter lancer beacon echo weaver siphon beam blade endless lowhp dead arc solo aura`（`aura` 摆的是燎灯那一圈停在半路的样子）。

万一哪天地图生成改了，报出来的会是这一句，而不是"分灯的引力失效了"这种假原因。

### 真实浏览器实测

`tools/playtest.mjs` 会用 Playwright 启动**真实 Chromium**，通过内置的零依赖静态服务器打开构建产物，
用真实键盘/鼠标走一遍完整流程，并把每一屏截图写到 `/tmp/wl/shots/`：

- 菜单 → 图鉴 →（打完一局后）点开条目看数值 → 生涯档案 → 今日灯芯（条件与剧本一致）→ 选灯火 / 难度 → 开局 →
  真实按键移动 / 冲刺 / 燃爆 / **分灯**（按 `E` 之后地上要多出一盏灯、自己的油要少一截、按钮要进冷却）/
  **拨芯**（按 `C`：灯火半径当场砍半、被照亮的那一片像素少掉六成以上、油条挂上冷色的牌子，
  同一个人站着不动 1 秒实测油耗是原来的 **0.35 倍**；再按一下半径与亮度都回到原来的量级、牌子收起来；
  那一屏存成 `03j-wick.png`。手机上点右下角那枚「拨芯」同样翻得动那个开关、按钮自己亮起来
  （`17b-mobile-wick.png`），而且它不压摇杆 / 别的按钮 / 底部连杀 / 右侧芯片。像素那一条要**先把场面清干净**
  再量——这一条量的是拨芯本身，不该被"恰好点着一座灯台"稀释掉（实测撞上过：不清场时只掉 17%））/
  **拨芯这条线（四件遗物）**（四件塞进手里 → 拨着芯 → 打开 `Tab`：构筑总览的「灯火」栏要把
  遮光 / 暗火 / 夜步 / 守芯 四件连条件一起写出来、滚得进视野、`1280×720` 上面板不被撑破，
  那一屏存成 `03k-wick-family.png`；图鉴的「拨芯」条目里也要点出这四件，
  而在那之前先只塞**一件**进去、这一局还没按过 C：主循环那一遍 0.75 秒的扫描要主动弹一张
  写着"要你先按 C"的说明卡（字、位置、尺寸都要对，那一屏存成 `03j0-wick-family-tip.png`），
  反过来已经按过 C 的人再扫一遍不许重复弹；这四件与灯芯在检查完都还原回去，
  后面的检查照旧；手机横带上同一栏也要如此——
  窄屏上那一行会换成三行，最容易出事的"横向溢出"就在那儿量，那一屏存成 `17c-mobile-light.png`）/
  **掠影**（把一只打不动的怪摆在路线旁边 44px，真按键从它旁边擦过去——要记一次数、要涨热度、

  走位那一套把两件事分开量：`wickOn` 是**意图**（按下那一帧就翻），`dimmed` 是**画面上真实的火**
  （插值过半，0.14 秒）——一开始只跑了 8 帧就断言 `dimmed`，红的其实是测试自己（0.133 秒还没过半），
  现在两句各量各的。
  面板那一头还有两条：**肩上那两枚**（LB / RB = 商店的第 5 / 6 件，战斗里按下去不该有副作用），
  以及**结算屏上 `Start` 是那颗主按钮**——摆成"被打死"之后按一下 `Start`，状态该从 `dead` 走到 `select`；
  少了它，手柄玩家打到死就卡在结算屏上（这个洞是这一版自己查出来的）。
  **"按着不放"这一族还多两条**：拔掉线时**不清**边沿状态（插回来时手还按着 Ⓨ，不该凭空翻一格——
  清掉反而是把"手还按着"读成"刚按下"）、`reset()`（切后台回**来**那一帧）记的是"现在按着什么"
  而不是清空；两条都是"玩家什么都没做，灯芯自己翻了一格"那一类，所以各有断言钉着。
  这一套 15 个"只改一行"的变异体（死区换成 0 / 换成 1、去掉边沿检测、十字键不接、斜推不归一、
  右摇杆死区与走位对调、面板上 `Start`/`Back` 换回战斗里那套、脸键顺序倒过来、只认第二只手柄、
  底部那行说明写回键盘的键、拔掉时清边沿状态、`reset()` 清空、肩键不接、拨芯不做出边沿、
  结算屏不进面板那一套键位）全部被杀掉。修订一次也对账过：**瞄准死区与走位对调**那个变异体
  第一轮**活了下来**——原来那句量的是 0.1，而 0.1 落在两个死区里都是"没在瞄"，
  两个数怎么换都测不出来；改成拿 0.2 卡在两个死区**中间**（走位认、瞄准不认）之后才杀得掉。
- `hotkeys`（补于 v81）：数字键从 `1~4` 接到 `1~6`（商店那六件货架——最下面两件是回血 / 回油，
  从前永远得挪手去点鼠标），所以这一套多量了两条：`Digit5` / `Numpad6` 读得出来，
  而"按 5 买的确实是第五件、扣的正好是那一件的价"。
  v82 起夜咒岔口也接上了数字键（这是四块"打断战斗"的面板里最后一块），
  而且这一条走的是 `panelHotkeys` 那条**路由**（不是直接调 `pickCurse`）——少了它，
  把路由那一句删掉测试照样绿（变异体实测活下来过）。
- `focus`（v82,「焦点环」）：这一套分两半。前半是**导航打分**（`pickNearest` 是纯函数）：
  只挑那一侧、同一列 / 同一行优先（底下那一项更远也一样挑它）、一条都没有才退回曼哈顿距离，
  以及"同列里正对着你那个优先"（前提先断言——偏右那颗按距离确实更近，规则仍该挑正下方那颗）；
  后半是**环本身**：第一次按方向只是"亮出来"（不猜你想去哪儿）、按住先 0.35 秒再每 0.11 秒一格、
  换方向立刻走、重画之后按身份回到原来那一项（设置里点一下开关整屏都会重画）、**换一屏则收掉**、
  看不见 / 禁用的东西不落环、`回车` 与 `Esc` 走的是和鼠标同一条 `click` 通道。
  最后两条走**整条路**：真键盘事件 → `Input` → 主循环 → 环 → 元素的 `click`
  （桩件里塞一份"可点的东西"进去，见 `tests/dom-stubs.mjs` 的 `focusables` / `backElement`），
  量的是"两下轻点（中间隔着松手那几帧）要走两格""环没亮时回车走那一屏的主按钮"
  "战斗里方向键照旧是走位、WASD 不喂环"——最后这三条都是这一版实测撞出来的洞，
  每一条都对应一个"改了不会报错、只会让手感偶尔不对"的写法。

### 性能体检

`tools/perf.mjs` 同样连真 Chromium，但量的是帧间隔、动态分辨率是否介入、以及高强度长跑 25 秒的
稳定性（报错数 / 堆内存增长 / 帧时间劣化）。它断言的是**相对改善**而不是绝对帧率——
没有 GPU 的容器里只有软件光栅化，绝对值天然难看，那正是动态分辨率要解决的问题：

| 场景 | 优化前 | 优化后 |
| --- | --- | --- |
| 1280×720 @1x · 高画质 | 27fps | **60fps** |
| 2560×1440 @2x · 高画质 | 6fps | **39fps**（动态分辨率压到内部 1152×648） |
| 25 秒噩梦无尽长跑 | — | 0 报错 · 堆内存 +0.0MB |

### 手机性能体检

`tools/mobileperf.mjs` 把游戏放进「手机横屏」的浏览器环境（默认 844×390 @3x、CPU 4x 降频），
并且支持**消融对比**（`KILL=bloom,light,...` 把某一步换成空函数再比总帧时间）——容器里只有软件光栅化，
绝对帧率不代表真机，但「每一步占多少」是稳定的。手机档（`core/Perf`）与改动前的对比：

| 手机横屏 844×390 · 自适应开 | v29 | v30（手机档） |
| --- | --- | --- |
| 平均帧时间 | 55.6ms（18fps） | **36.1ms（28fps）** |
| 每帧画布命令数 | 3963 条 | **3330 条**（−16%） |
| 光照贴图分辨率 | 与画布同分辨率 | **半分辨率**（翻倍放大，柔光看不出） |
| 泛光 | 1/4 采样 · 两层叠加 | **1/6 采样 · 单层叠加** |
| 定分辨率 844×390 · dpr1（v33 → v34 → v37 → v39） | 46.3ms（22fps） | **30.6ms（33fps）** |
| 自适应（手机上真正的默认跑法，v30 → v37 → v39） | 36.1ms（28fps） | **18.3ms（55fps）** |
| 暖光精灵（v38 → v39，定分辨率 dpr1） | 35.6ms（28fps） | **30.6ms（33fps）**（−14%） |
| 整帧渲染 · 冻结基准（v44 → v45，手机 dpr1 / 桌面 1440×810） | 21.1ms / 68.4ms | **19.8ms / 61.8ms**（−6% / −10%） |

真机上还有两项量不到但更实在的收益：**屏幕 120Hz 时限帧到 60**（同一块画面不画两遍），
以及竖屏时**整个主循环停摆**。

## 已知取舍

- **面板热键只挂了"选哪一张"，没有给"退出去"配键**：升级卡 / 祭坛 / 商店那三块面板上的
  数字键选的是一份**游戏状态**（拿哪张卡、花多少钱），点错了顶多损失一次机会；
  而"原样离开祭坛""离开商店"是**一次性且不可逆**的（离开之后那座祭坛不会再开、
  补给站也回不去）。`Esc` 在战斗里已经是暂停键，玩家被打死的那一瞬间手往往正按在它上面——
  把"离开"接到一个会被人反射性按下的键上，代价是有人会莫名其妙丢掉一座祭坛。
  所以那几颗按钮仍然是鼠标/手指的活；`回车` 只接了结算面板上那颗**读过之后**的主按钮。
- **「薪火」为什么比树贵一个数量级，而且要封顶**：它是**余烬的去处**，不是第二棵树。
  树上那 16 个节点（2560 余烬）是"从零开始把底子铺起来"，而炉子是"铺完之后每一局仍然有一级可点"——
  两件事的目标不一样，价格就不该一样：如果炉子也按 60 余烬换 +18% 那样定价，那条"先买树"的
  自然顺序就被打乱（新手会在最该买树的时候把钱烧进炉子，而面板上那句"还剩 N 个节点"救不了他）。
  封顶（三条共 18 级）也是刻意的：不封顶的话，这个系统的终局就变成"比谁攒得久"——
  噩梦、深宵之约、无尽之夜这几条线全部失去意义（玩家最后比拼的是刷了多少局，不是打得怎么样）。
  代价是这条线**不会让老玩家重新变强到改变打法**（18 级满级 ≈ 一条武器的两级），
  它只是一口炉子：让"余烬"这个数在买无可买之后还有一个去处。
- **元进度第一次动火力（+24% 封顶）**：v80 之前，解锁树上一条改伤害的节点都没有——
  火力是这游戏里最贵的那个数（它同时是清场速度、生存能力与"能不能扛住之约"），
  所以它被留给局内的升级与遗物。炉子这一条是唯一的口子，而上限就卡在 **+24%**
  （六级的量，约等于一条武器的一次升级）；更重要的是它走的是 `Player.metaMods`
  （和「夜行」的移速同一个位置），所以拿到遗物重算一身属性不会把它冲掉，
  被拉掉遗物也不会把它顺手收回——局外那几笔和局内那几笔，各走各的账。
- **手柄为什么只认第一只、不给自定义键位、菜单那几屏也先不接**：`getGamepads()` 的顺序就是"第一只"，
  两只手在同一个角色身上抢方向盘（谁推得多听谁的）只会让人以为游戏坏了，所以直接认第一只。
  键位写死的是**标准布局**（Xbox / PS 上手柄那四枚脸键的位置本来就一样，`Ⓐ` 在下、`Ⓨ` 在左），
  自定义键位要先有一套"按一下要按哪儿"的界面、冲突检测和存档字段——而这些键位恰好是玩家的肌肉记忆，
  先按标准布局来；代价是习惯另一种布局的人会觉得 `Ⓐ` / `Ⓨ` 是反的（真要改就是下一版的事）。
  菜单那几屏**到 v82 才接上**（焦点环，见「操作」那一节）：在 v81 里手柄玩家的开局还得摸一次鼠标——
  手柄没有指针，"开始冒险"那颗按钮点不动。这一条现在补上了，代价是**同一颗键在两个情境里是两个意思**：
  `Start` 在战斗里是暂停、在菜单里是"开始冒险"（`Esc` / `Ⓑ` 也是：战斗里暂停 / 分灯，菜单里返回）。
  这一层只能靠"玩家现在正看着哪一屏"来判断，所以文档与 HUD 那行提示都得跟着说清楚——
  两个设备之间切换时不该长出第二套直觉。
- **焦点环在"第几张"那四块面板上不亮**（升级 / 商店 / 祭坛 / 夜咒）：那四块本来就用数字键 / 脸键
  直接挑（`1` … `6` = 第几张），同一个位置再摆一套"环挪到第 3 张"只会互相打架——
  玩家按了 3，屏幕上却有一圈光停在别的地方，谁也说不清按下回车会拿到哪一张。
  代价是那四块面板上**环不出现**，键盘 / 手柄玩家在那一屏靠数字键与脸键（那条路 v68 就通了）。
  另外三块"打断战斗"的面板之外还有一处：**鼠标悬停不挪环**（`hover` 与 `focus` 是两回事）——
  所以那十几屏上四条路并存，各走各的，不会因为"鼠标恰好停在哪儿"而让回车按下别的东西。
- **环为什么"第一次按方向才亮、换一屏就收掉"**：手机上根本没有这个环（它只在按过方向之后出现），
  一直挂着会让人以为"这里有个能点的东西"。换屏收掉是实测撞出来的：不收的话环会"记得"上一屏的第 4 项——
  从图鉴按 `Esc` 回主菜单，没按方向右边那一列就挂着一圈光（还圈着「生涯档案」之类的东西），
  看上去像是上一步点歪了。代价是每次换屏都要再按一下方向才看得见环；
  而"原地重画"（设置里点一下画质那一排、选灯火里换一盏灯）**不会**收——
  那两种情况元素按身份（`data-act` / `data-lantern` / `data-quality` …）找得回来，
  环留在原来那一项上，不会掉回第一项让人迷路。
- **"同一列"是结构性的规则，不是加权距离**：第一版用的是"主轴 + 2×侧轴"那种加权距离，
  台架一量反而更差（解锁树 38 下同列候选里跨列 6 下 → 加权之后 8 下）：在**子项宽度不一**的网格里，
  "侧向要更贵"这个直觉不成立。换成"先看侧轴投影有没有交叠"之后是构造性的——
  同列候选存在时不可能挑到别列去。代价是**同列里那个远的也会赢过旁边列里那个近的**
  （主菜单实测：从「开始冒险」按"下"一定落在左列的无尽之夜上，哪怕右列顶上那颗更近）；
  这条规则还顺手把"正下方"那一层也钉住了：并排两颗到那颗大按钮的距离只差两像素时，
  按"侧向偏得少"排一次，按键的结果不随版式的几像素抖动翻脸。
- **手柄的菜单导航死区是 45%（走位是 18%）**：菜单上"手搭在杆上"是个**静止**动作——
  玩家一边看面板一边把拇指放在杆上，回中不准的杆会一直报 0.2~0.3，那个量级够把环一格一格推走
  （实测：0.3 在走位那套里已经算在动了）。代价是菜单里推摇杆要推得比战斗里更明确一点；
  十字键不受影响（它是个数，不是个量）。
- **方向键在战斗之外**不再是走位（战斗里它和 WASD 一样）：这是**同一份按住状态两种用法**，
  名字在 `Input` 里就分开了（`moveX/moveY` 与 `navX/navY`）——不然战斗中按 `A`，
  环会跟着一起动，只是恰好被"战斗里不挪环"那条门禁挡住，那种"靠门禁兜着"的写法迟早会出事。
- **手柄"按着不放"的那一下永远不算新按下**：拔掉线再插回来、或者接到电话切出去又回来（主循环会调
  `pad.reset()`），只要那一刻手还按着 Ⓨ，这一下就**不算**一次新按下——清掉边沿状态反而会把
  "手还按着"读成"刚按下"，玩家什么都没做、灯芯自己翻了一格（这一条是这一版写测试时自己撞出来的）。
  代价是：真拔了线再插、又恰好按着同一个键时，得松手重按一次才认。两害相权，选"少一件玩家没做过的事"。
- **「分灯」买到的秒数完全取决于你把它摆在哪一边**（v83 量出来的）：台架上四种走位各跑 30 秒
  （12 只影蛭在身后 260px、玩家不还手），同一盏灯买到的"第一次被贴上"差了整整三秒：
  站桩把它摆在脚下 **±0.0s**、直线逃跑时把它丢在身后（正好落在追兵本来就要路过的线上）**±0.0s**、
  绕圈 **±0.0s**、**拐个弯把它留在你不去的那个方向 +3.2s**。这是刻意的，也是这一族四件存在的理由：
  一个"按一下就有用"的技能会让位置这件事失去意义，而这一局的全部赌注都压在"你站在哪儿"上。
  代价是**它很挑**——不看台架、只凭手感，玩家多半会把它当成一个没用的键（实测那三种用法里
  有两种挡住了 50 只·秒以上，却一次都没让你晚挨打）。所以图鉴 / 教学卡 / 新加的那张说明卡里，
  讲的都是"摆在哪一边"，而不是"按 E"。
- **「焚灯」让这个动词的最优解多了一道权衡**：它把"灯被啃掉"这个默认结局变成一次爆炸，
  而爆炸的收益直接跟着"你引来了几只"走——可引来的那几只**正在吃你放出去的那盏灯**，
  而且它们只在灯的光里（引怪圈内）才算。于是最强的那种用法（把一群怪聚到一盏灯上）也最贵：
  灯灭得越快、你那一成四的油越快没；想炸得狠就得让它们靠近，想省油就得挑个远处的位置。
  **这条没有"正确答案"**（台架上 12/12 全中那一下是排得整整齐齐的靶房，真打起来不会这样），
  它只是把"分灯"从一个便宜的拖延手段，变成一个要算收益的动作。
- **手柄不做震动**：手机上那套触感（挨打 / 濒死 / 升级 / 死亡）走的是 `navigator.vibrate`，
  而手柄震动是另一套 API（`gamepad.vibrationActuator`），只有部分浏览器 + 有线手柄才稳，
  而且"同一个动作震两下"（手机震完手柄再震）比不震更糟。先把键位与手感这一层做实，
  震动留给真机上量过延迟之后再说。
- **「深宵之约」为什么是一条一条加，而不是第四档难度**：第四档只是"同一张题做久一点"，
  而这一套要改的是**打法**——所以七条各自只改一件事，而且**每条一样贵**（+15%）。
  不按"这条有多难"分别定价是有意的：那需要一张经得起推敲的难度权重表（"视野 -12%"和"敌人血量 +30%"
  哪个更狠？取决于你的构筑），算出来的价只要偏一点，玩家就会去挑"最划算的那条"，
  而这一套要问的问题只有一个——"这一局你想背几条、你敢背几条"。
  同理，条款一律不接受"只在某种构筑下才生效"：那种条款对另一部分玩家等于没加
  （「拨芯那四件在没有拨芯的人手里是废牌」是同一个坑），所以这里没有"禁用复燃""不能重掷"这类
  只在有那个元进度时才有意义的条款。代价是这套东西的上限就是"同一个游戏更难一点点"，
  它不会长出新的玩法——那是武器与遗物那条线的活。
- **今日灯芯不吃「深宵之约」，而且它只认生涯档案里的那个数**：那一天所有人共用同一道题
  （灯火与难度都由日期定），谁能背几条就等于谁的成绩不成立，所以每日开局时这一套**整个丢掉**
  （不是"界面藏起来"——藏起来只挡得住界面）。钥匙也直接读 `records.clearedRuns`（生涯档案里
  早就有的那个数），不另存一个开关：多一个开关就多一条"它和那个数哪个才算数"的第二种真话，
  而且老存档（已经通关过的人）会自动拿到这一套，不用再打一遍。代价是这道门**关不掉**——
  通关过一次的人永远看得见这一排，哪怕他从来不勾（那一排会说"这一局没背 · 平常的一夜"，
  顺便承担"这东西在哪儿"的指路）。
- **「重掷」曾经是一块死面板（v68 修）**：升级面板是一张静态 DOM，卡片点下去时按屏幕上
  那个 id 回 `offers` 里找，而重掷是**唯一**一次"面板还开着的时候换掉那份数据"——
  从前它只更新数据、不重画，于是屏幕上留着上一把牌：轻则点了没反应（屏幕上那张卡在新一份牌里
  不存在），重则重掷点花完了、按钮写着旧数字、整块面板一张都点不动，只能刷页面。
  修法是在 `Game.reroll()` 里换完牌就 `showScreen('levelup')` 重画一次，
  并且真实浏览器实测里钉了三条（面板上的牌 === 手里的牌、没有孤儿卡、换完牌照样点得动）。
  之所以一直没人撞上：重掷点数是局外解锁出来的，默认存档里是 0。
- **「拨芯」压不住已经点着的火，而火焰流因此亏得最少——这是刻意的**：拨芯对火力动的那一刀，
  账面是 **×0.65**，但同一个武器打同一群不动的怪，贴脸（110px）只掉到 **89%**、中距（240px）才掉到 **66%**。
  差的这一截全在**灼烧**上：拨芯拨的是"你自己这盏灯"，而灼烧是**已经点在怪身上的火**——
  那团火不在你的灯里，拨芯够不着它。于是烈焰鞭 / 倾灯这类靠"先点着、再慢慢烧"的构筑在这一刀里亏得最少，
  纯瞬时伤害的（光矛 / 回旋灯刃 / 雷弧）才真的掉到 65% 上下。
  为什么不干脆让它一刀切全场：那样拨芯就变成一枚"关掉自己伤害"的开关，"暗着走"在任何构筑上都只剩余罪，
  而这一版要的是"要暗，还是不要暗"这个**有来有回**的取舍。口径也一致——`damageScale` 里它是**最外面**
  那一层（爆灯 / 灯焰高涨 / 低油增伤都在它里面，一起被压下去），而灼烧走的是
  `EnemySystem.applyBurn` 自己那条账，两家不串门。
- **「拨芯」在屏幕上没有自己的图标，只有油条上那枚牌子**：冲刺 / 燃爆这类"按下去要付代价"的东西都画着冷却圈，
  拨芯是个**没有冷却的开关**，所以没有圈可画。它多出来的指示只有两处：**灯油条上那枚冷色的「拨芯」牌子**
  （`is-dim`，门槛用插值后的 `player.dimmed`（过半）而不是 `wickOn`——按下的那一瞬间火还没矮下去、
  牌子先亮了会被读成卡顿），以及触屏按钮自己的高亮（构筑总览里的「灯火」一栏同时冷下来）。
  **这个门槛 v70 起是"有规则意义"的**：那四件拨芯遗物、成就 `wickwalk` 和这枚牌子看的是同一个 `dimmed`
  ——"拨着芯"在规则上只能是一个数，界面上也只好是同一个，不然会出现"牌子亮着、遗物却没生效"这种
  谁也查不出来的错。它原来写的是 `wick > 0.35`，改成过半之后触发点晚了 0.04 秒（拨小一共 0.28 秒），
  眼睛看不出来。
  之所以敢只留这两处：拨芯最响的反馈不在 UI 上，而在**世界本身**——实测（满油附近）半径 318px → 158px、
  亮度 0.884 → 0.397、屏幕上"被照亮"的像素从 30.6% 掉到 7.6%，那真的黑下去一大块，
  不需要再挂一枚图标去解释。留着的两个风险：那 0.28 / 0.42 秒的过渡里牌子与画面会有几帧不同步；
  以及色弱的人可能读不出那抹冷色——牌子旁边仍然写着「拨芯」两个字，不靠颜色认。
  它也不进结算与生涯档案（它没有"分数"可记），唯一记账的地方是成就「省着烧」。
- **「漫光」和「拨芯」写在同一个数上，一局只该选一边——这是刻意的，也是这一版最容易买错的一笔**：
  两条路改的是同一个 `player.lightRadius`，方向相反：拨芯把它砍到 158px（满油 318 → 158）、
  漫光把它推到 352px（320 × 1.1）。为什么不做成"两个都能要"：灯火半径同时是**索敌范围、照亮范围
  和燎灯的射程**，能同时要的话"亮着烧"就没有反面了——那就不是取舍，是把两个加成叠在一起白拿。
  代价是有人会同时买下这两件（店里不会拦），身上就是两笔互相抵消的账，而界面上看不出来。
  所以能做的只有**把它说出来**：两族的数写在构筑总览的同一栏里、图鉴的「燎灯」条目里明说
  「漫光」和「拨芯」对着干、遗物说明里各自写着对方那半句话。
- **「燎灯」那四件，对"武器位里没有燎灯"的人同样是四张废牌**：旺火 / 吮灯 / 烟熏改的全是
  `kind: 'aura'` 那一件武器的行为（多罩一只更重、烫到回油、烫到变慢），而燎灯是要在升级面板里
  **抽到**才会在手上的——没抽到它的人，这三件在整局里一个数都不动。这和「拨芯」那四件是同一种代价
  （围绕一个机制的遗物，买的就是"你会不会用那个机制"），规矩也一样：不补数值，只把条件写出来。
  唯一不同的是「漫光」——它改的是**这盏灯**本身（半径与油耗），不拿燎灯也照样生效，
  所以它在这一族里是"随时能拿的那一件"，另外三件是"为燎灯准备的"。
- **拨芯那四件遗物，对"从不按 C 的人"就是四张废牌**：它们只在 `player.dimmed` 时生效，
  而拨芯本身是一个**要自己去按**的动词——没按过 `C`（也没点过手机上那枚按钮）的玩家，
  抽到这四件等于什么都没抽到。这是刻意的（和「焰路」那四件同一个规矩：围绕一个机制的遗物，
  买的就是"你会不会用那个机制"），但代价是真的：68 件里有 24 件对一部分人不存在
  （拨芯这 4 件 + 「燎灯」那族里"只为燎灯准备"的 3 件 + 「倾灯」这 4 件 + 「伏灯」这 4 件 +
  「旋灯」这 4 件 + 「弃灯」这 4 件，另 1 件是人人能用的漫光）。
  所以补的不是数值，而是**把条件说出来**——图鉴里「拨芯」那一条单列一行"专为它准备的遗物"、
  构筑总览的「灯火」栏把身上那几件连条件一起写出来、第一次拨小时还会弹一张说明卡。
  v72 又补了最容易漏的那一格：**第一次拿到这四件里的任何一件、而你还没按过 C** 的时候，
  也会弹一张"这件要你先按 C"（弹出过、或者你自己已经拨过芯，就不再打扰）。
  它盯的是"身上有没有这四件里的任何一件"（名单 `WICK_FAMILY_IDS` 是从遗物的 `mods` 里认出来的，
  不是手抄的 id 表），而不是某一条获取途径——这四件有五个入口（精英掉落、商店、祭坛、熔铸、旧灯），
  逐个入口挂等于把同一句话抄五遍，将来漏一处也没人看得出来。
  而"要不要为了它们改成暗着打"仍然留给玩家自己算。
- **燎灯和「拨芯」那四件是同一条轴的两端，凑在一起就是互相拆台**：燎灯的射程**就是**灯火半径，
  拨芯把半径砍一半（面积只剩四分之一），再叠上 `damageScale` 那一刀 ×0.65——同一间靶房里，
  **还在光里**的那圈靶读数从 482.7 掉到 313.8，而只要靶子挪到 240px（拨芯后 160px 的圈外面）
  就是一只都挨不到；偏偏「遮光 / 暗火 / 夜步 / 守芯」那四件只在拨着芯时生效。也就是说一个构筑里
  同时拿到燎灯和它们，两边的钱都只花了一半。这是刻意的（和「焰路」那四件、拨芯那四件同一个规矩：
  围绕一个机制的牌，买的就是"你会不会用那个机制"），但代价也是真的：随机抽到燎灯、而这个人又刚好
  走的是"摸黑打"那条路，会有一局觉得这一件是空的。补的办法不是把数值往两头掰（那只会让"两条路都走"更亏），
  而是**把这件事说出来**——图鉴「机制 · 燎灯」单列一行讲清它和拨芯为什么是对着干的、
  构筑总览的武器行上写「光里全体」、拿到手的那一刻再讲一次它的射程写在灯火上。
- **「伤害构成」里的灼烧记在"最后点着它的那件武器"头上**：灼烧是每帧从怪身上扣的
  （`Enemy.applyFrame` 里 `burnDmg = burnDps × 层数 × dt`，和帧率无关、也没有"几秒一跳"），
  而同一只怪身上的火可能被好几件武器轮流续过（烈焰鞭点着、倾灯往上倒油、遗物再添一层）。
  要逐层记来源，就得在每个敌人身上挂一摞小账，而收益只是把"三层里的那一层"换个名字；
  这里选的是"谁最后点的火，这一跳就算谁的"（口径写在 `EnemySystem.applyBurn` 的注释里）。
  单场结算时它仍然读得通——谁点着的火，谁认这口账。
- **那张表有一条兜底的「其他」，真打一局基本不该看见它**：它接的是"进账时没报名字"的那种账
  （程序化入口，比如测试里直接调 `placeMine` 摆一颗雷）。留着它是因为"账不能丢"——
  宁可表上多一行说不清名字的，也不能让各来源之和与"造成伤害"对不上。
  实测过两遍：离线把六个武器位塞满跑 60 秒游戏时间（十个来源全带名字、`其他` 是 0），
  真实浏览器里以同一条件跑 90 秒也一样；它第一次露头反而是**实测脚本自己**造成的
  （`tools/playtest.mjs` 直调 `placeMine` 时漏了第 7 个参数）。
- 真实浏览器实测需要 Playwright 与 Chromium（首次需联网下载）；离线环境下只能跑 `npm test` 的软件光栅化方案。
- 软件光栅化器（`tools/softcanvas.mjs`）只实现了游戏实际用到的 4 种混合模式
  （`source-over` / `lighter` / `multiply` / `destination-out`），换用其它混合模式时请改用真实浏览器验证。
- **「掠影」的数值是按脚本实测调的，但脚本不是人**：手感这种事只能靠"莽夫 / 会跑 / 贴着打"三种脚本
  的对比来卡区间（详见 `src/data/graze.ts` 里的注释），真按人的走位可能偏松或偏紧。
  改这一块时先跑 `tests/graze.test.mjs` 钉住规则，再动 `GRAZE` 里的数。
- **「焰路」那四件遗物在中段收益最大，顶端已经饱和**：拿脚本量过（`tools/` 外的临时台架，
  一排怪里来回穿的极端脚本 60 秒）——裸奔 8 次焰、覆盖率 83%，带上焰心还是 8 次 / 84%，
  带焰心 + 长风是 6 次 / 90%（每次更长、次数更少）。也就是说"完美贴着打"的脚本本来就贴着上限，
  焰心的收益主要落在**还没到那个水平**的人身上；这是刻意的——它该把"敢贴"教会，
  而不是给已经会玩的人再多加一圈伤害。
- **「伏灯」的强弱完全取决于你怎么走，而且这个差距是量出来的**：它不像别的武器"打出去就有收益"——
  埋下去之后要靠敌人自己走过来。台架上（12 只打不死的影蛭追着你跑、只带这一件、60 秒、四种脚本走位，
  每种跑 5 遍取平均）：

  | 脚本走位 | 撒下的雷 | 被踩响 | 一次炸到 | 单件 DPS |
  | --- | --- | --- | --- | --- |
  | 绕圈跑（离线台架里最笨的那种） | 65 颗 | **13%** | 2.3 只 | 32 |
  | 来回拉（拿自己的雷当路用） | 64 颗 | 51% | 9.3 只 | 693 |
  | 蛇形（转得急，来回穿自己的雷） | 65 颗 | 99% | 9.2 只 | 616 |
  | 一直朝一个方向跑（撞墙被堵住就是最危险的时刻） | 62 颗 | 76% | 9.2 只 | 1128 |

  同一台架上的参照：爆裂火球 1002 / 2634 / 2434 / 2046，光矛 493 / 1155 / 692 / 1125。
  也就是说"会用自己的足迹"的走位能把它拉到和火球一档，而只会绕圈的走法几乎等于空着那个武器位——
  这一条是**刻意的**（这一版的整个题目就是"位置可以攒"），但代价是：随机抽到它的新手会有一局
  觉得它没用。补的办法不是把伤害调高（那会让会玩的人更强），而是把"雷躺在哪儿看得见"做清楚
  （灯身 + 虚线触发圈 + 上弦进度弧），以及把寿命从 8 秒抬到 10 秒把最差的那一档从 11% 拉到 13%。
  v73 起这张表多了一个**进仓库**的复跑方式：
  `node tools/bench-weapons.mjs --weapon=mine --walk=circle|sweep|zigzag|straight --secs=60`
  （同一间靶房：12 只打不死的影蛭追着你跑、只带这一件、60 秒、同一颗种子——两次跑出同一份数）。
  按上表那四行的顺序量到的单件 DPS 是 **25.8（绕圈跑）/ 1327.1（来回拉）/ 1147.8（蛇形）/ 1432.9（一条道跑到黑）**
  ——形状和上表一模一样（绕圈 ≪ 蛇形 ≈ 来回拉 < 一条道跑到黑：绕圈那一档只剩二十几，另外三档都上千），
  绝对值不同是因为靶房和那四种走法都是新写的。上表那几列（撒下几颗、被踩响几成、
  一次炸到几只）还是出在旧台架上——`--walk` 这一档只报 DPS 与覆盖，想复查那几列得回到同一个旧台架。
- **「连爆」的触发率同样是量出来的**：连锁半径给多宽（`chainReach` × 爆炸半径），决定了它是"一串涟漪"
  还是"一团白光"。同一台架（12 只打不死的影蛭、只带满级伏灯、60 秒、四种走位、每种 3 遍取平均），
  记下**每一颗雷最后是怎么没的**——被怪踩响、被引信串响、还是自己烧尽：

  | 走位 | 撒下的雷 | 踩响 | 被引信串响 | 自己烧尽 | 串响占比 | 最长一串 |
  | --- | --- | --- | --- | --- | --- | --- |
  | 绕圈跑（一路不回头） | 65 | 55 | 4 | 0 | **7%** | 2 |
  | 来回拉（回头穿自己的旧雷） | 64 | 32 | 18 | 8 | **36%** | **4** |
  | 蛇形 | 64 | 32 | 32 | 0 | **50%** | 2 |
  | 一直朝一个方向（撞墙被堵住） | 61 | 31 | 28 | 0 | **47%** | 2 |

  两种不一样的串都在这张表里：**同一把枪一次撒下的两颗**（间距 16px，永远够得着）让"每一次开火"
  本身就是一小串——所以连爆不是偶尔才出现的特效，而是将近一半的爆炸都会发生；
  而更长的串（3~4 节）只在**回头穿过自己旧雷**的走法上出现，那正是这一版想教的东西：
  撒得密是一串，撒得开是一颗一颗，两种都对，选哪种取决于接下来那几秒你想让这段路怎么死。
  一串的引信是 0.09 秒（约 5 帧）一节——不是同一帧一起炸：同一帧一起炸看见的只是一团更大的白光，
  一串依次烧过去才看得出"这是个串"，听起来也是一级一级往上走的（音高随节数升高）。
- **「以灯为饵」的门槛是量出来的**：蛾扑的是最近的那盏光，所以"把一群蛾引到同一盏灯上"是个**手法**，
  不是运气。台架上（12 只蛾一直扑、只带满级伏灯、60 秒、三种走位）：一分钟里"炸到蛾"的雷约 35 次，
  其中**一次炸到 4 只**的只有 2~4 次（一次炸到 1~2 只的占了绝大多数）。
  所以成就的门槛定在"一颗雷一次炸到 4 只"，而不是"单局累计炸到 N 只"：后者的数越攒越多，
  随便扔雷也会够——那就不是在考"引它们过来"了。
- **「旋灯」的吸力是有梯度的，收缩那一下又比吸入圈小一圈——这两条都是刻意的**：
  台架上摆一只不动的影蛭、让它从各个距离出发、拽满 1.2 秒（半径 116 / 吸力 175）：
  0.93R 以内的**一律被拽到中心**（从 100px、108px 出发都收到 0px），再往外才慢慢掉队
  （0.97R 挪 102px、0.99R 挪 76px 停在外沿 39px 处）——"站在线里的都会被收走"这句在圈的内九成是真的，
  最外沿那道缝是留给"贴着边跑过去"的。首领从头到尾只挪 22px（约等于不动）。
  （v57 那版是线性衰减：0.86R 以内拽到中心、0.97R 只挪 19px、0.99R 只剩 5px——画出来的圈和真的力道
  是两回事，外侧站在线里的怪一步不动。v58 把外侧垫起来就是为了让那道边界说话算话。）
  代价是它单发的伤害很薄（1 级 24），而收缩圈只有吸入圈的 72%——所以它不该被当清场武器用，
  也不能当定身符：它是一件"给别人打下手"的武器，和燃爆 / 光矛 / 雷弧 / 伏灯摆在一起才有价格。
  改这一块时先跑 `tests/vortex.test.mjs`（里面有一条专门钉"吸力和帧率无关"，见上面 `vortex` 那一条的坑）。
- **「收网」的门槛数的是"只数"，不是"伤害"——这是量出来的，不是拍脑袋定的**：
  最早写的是"收尾打出 120 点以上"，60 秒台架（12~16 只打不死的影蛭、只带旋灯、三种走位）一量才发现
  这个数立不住：干油的时候，满级旋灯在 12 只的场面里最狠只摸到 **116**（离 120 差 4 点，怎么打都差一口）；
  而满油的时候它 6 只就够——因为收尾伤害 = 基础 × 灯火系数 + 6 × 只数，基础随等级 24→68、
  灯火系数随油量在 0.65~1.35 之间飘，**同一个玩家做同一个操作，账能差两倍**。
  更糟的是进化那把（基础 166）：满油时空放一下就有 224，成就等于白送。
  门槛要是随这两样飘，它就不是在考操作了——所以改成"一次收网打到 10 只"。
  只数跟等级、跟油、跟难度都没关系，只跟"你有没有把它们拢住"有关系，而那才是这一版要考的东西；
  代价是它变成了**场面型**成就：一波两三只的场合根本解不开，非得真有一窝东西站进那个 83~109px 的收尾圈里。
  （顺带一个台架上的坑：台架里不补油的话，跑满 60 秒灯火就烧干了，量出来的全是"干油那一档"的数——
  第一版结论"满级最狠 116、够不到 120"就是这么来的。真实情况是灯亮时同一个操作能多出近一倍的账。）
- **「标灯」放大的是"打出去的那一下"，灼烧不吃它——这条是刻意的，代价是烧灯流派拿它基本等于白拿一件**：
  它是全项目**唯一**一件在 `applyHit` 里往上乘的遗物（别的遗物都在更前面改玩家的属性），
  于是燃爆 / 光矛 / 雷弧 / 火鞭 / 倾灯那一片火海的**直击**都吃那 25%，
  而已经点在怪身上的**灼烧**不吃——灼烧是在怪身上每帧自己扣的（见上一条），压根不经过 `applyHit`，
  和「拨芯」不吃灼烧是同一条规矩：火已经烧起来了，不该再被"你现在站在哪儿"这个位置条件二次加成。
  台架上量得清清楚楚：没拿这一件时圈里圈外一样疼（100.0 → 100.0），带上之后圈里 125.0（正好 ×1.25）。
  代价是：堆灼烧的构筑（燎灯 / 倾灯的续燃）拿到它只是一件 +25% 的直击小卡，
  那 25% 只有在"先用旋灯拢住、再补一发直击"那条路上才拿得到——而那正是它想要的。
  补的办法照旧是把条件说出来：图鉴的「旋灯」条目单列一行"专为它准备的遗物"、
  构筑总览的「旋灯」栏把那四件连条件写上。
- **伏灯的天敌是"性格"，不是数值**：吹灯客走进触发圈就把雷吹灭，这是**硬克制**（那颗雷一定不炸）。
  我们没给它加一条抗性数值，也没让玩家算概率——它就是把"你的触发圈"反过来用：它进得来，就吹得灭。
  代价是：带伏灯的一局里，第一次撞上吹灯客会白丢几颗雷。补的办法是让这件事**看得见、说得清**——
  成对的紫烟（不是爆炸）、结算里那一行「被吹灭 n 颗」、图鉴「机制 · 伏灯」里的「怕吹灯客」一行，
  以及吹灯客自己的说明里那句"你埋的伏灯它也照吹不误"。玩家该学到的是"先点掉它"，而不是"这武器坏了"。
  代价：最坏情况（站着不动，六颗雷堆在脚边）每一帧都在连锁，但那是"六颗封顶 + 每节只隔 0.09 秒"
  里的一次线性扫描，成本可以忽略。
- **「倾灯」的收支是量出来的，而且它刻意不设"倒得起就行"的低门槛**：一瓢 0.15 桶，而灯的进项是
  击杀掉落（每只 0.4%~1% 上下）、擦身回油 0.8%、红灯区的油 4%、灯台 6%；出项只有每秒 1.8% 的自然衰减。
  台架上只带这一件、12 秒不补油：倒得出 **2 瓢**（末油 0.51）——也就是说**光靠自然衰减，它是攒不回来的**，
  想让它一直响就得去打、去擦、去点灯台（那正是我们想要的：它把"捡油"从一件顺手的事变成一件要做的事）。
  真机上同一个位置是 3~4 瓢，因为击杀掉落与掠影都会补。
  门槛为什么不设成"有多少倒多少"：那样它会变成"油一有就被倒掉"，玩家的灯火会被这件武器常年摁在低位——
  那不是取舍，是它在替玩家做决定。卡在 72% 之后，倒的永远是油桶最上面那一层，手里始终留着大半桶油过日子。
  代价是：**油量低的构筑（「枯灯 / 低语」那条自伤线）几乎带不动它**，两件东西抢的是同一个池子，
  这是刻意的——它俩本来就该是相反的两种玩法。
- **「倾灯」那片火不烧自己，是刻意的，而且只豁免它一个**：它是自动开火的武器，
  罚一件玩家没有主动按下扳机的东西不叫代价、叫冤枉；它的代价写在油上。别的火（爆裂菇的词缀、
  连珠伏灯留下那层、陨石雨）照旧烧玩家，`Ground.ignites` 这一个开关就是这条界线。
  顺带一个画面上的坑：那片火的**火舌画在敌人之上、玩家之下**——一瓢的落点永远是自动瞄准锁着的那只怪，
  所以火心必然被一群怪盖住；全画在实体底下的话，最该被看见的一团火就只剩一圈边。
  而玩家仍在火舌之上，不然"我站在哪儿"会被自己的火吃掉。
- **「拾油」按瓢封顶，是刻意的"收得回来，但收不回本"**：一瓢最多收回它**自己代价**的六成
  （`POUR.emberCap = 0.6`，见 `src/data/pour.ts` 里那一段算术）。算术很直白：满级一瓢花 10% 的桶，
  而一片火海常常同时点着十几二十只——每只回 0.5% 的话，一头撞进 25 只的怪群里一瓢就能收回 12.5%，
  比它花掉的还多。"油"这个资源当场失效，倾灯会从"什么时候倒"变成"一直倒"，
  而这一版所有的取舍都长在"油是稀缺的"上。六成奖励的是"往人堆里倒"这个判断，
  它不奖励"倒得越多越好"。台架上这四件是分开量的：1 只 0.500%、4 只 2.000%（正好 ×4），
  20 只咬在 6.12%，而不带这一件第一只就是 0。
- **「伏灯」这一族的四件，对"不拿伏灯的人"就是四张废牌**：它们改的全是"撒下去之后"的事——
  地上能留几颗、连爆够得着多远、蛾从多远闻得到、踩响的拖住多久——手里没有伏灯（或者它的进化）
  就一个数都不改。这是刻意的，和「倾灯」那条线同一个规矩：围绕一件武器的遗物，买的本来就是
  "你会不会用这件武器"；而它和「掠影」那四件的区别在于，掠影是人人都有的一条机制，
  伏灯是一件要**拿到手里**的武器。所以那一栏也只在手里有伏灯时才画——没有它的玩家在那儿
  只会读到一行"地上 0 颗"，那是占地方。
- **「伏灯」的上限抬到 8 颗，是抬、不是拆**：不给上限的话，一路小跑就能在地上铺出一条雷带，
  之后画面上所有事都变成"等怪走到我铺好的路上"——那太省事了，也不好看（这一条从 v66 就写着）。
  「灯阵」多给两颗，是为了让"铺一条路"这个玩法做得成，而不是把它变成唯一解；
  同一条道理也在寿命上：10 → 13 秒只是"追兵走到你八秒前站的地方时，那颗雷还在"，
  不是"埋下去就不用管了"。
- **「香饵」把"以灯为饵"从一次操作变成了一个小循环**：引蛾的距离 +50%（380 → 570px）之后，
  蛾会从你看不见的地方拐过来；而被炸死的蛾每只回 0.5% 油，是这一族唯一的进项。
  它刻意**只认蛾**（影蛭炸死在雷上一滴不回）：那口油是"它扑的是光"这句话的结果，
  而不是"伏灯变成了一口油井"。代价是这条循环只在有蛾的波次里转得起来——
  而蛾是按波次配的，不是每波都有，所以它不是一条稳定的收入，只是一次划算的交换。
：它们买的是同一件事情的三个方向——
  收着烧、照着烧、泼出去烧——玩家的决定本来就是"我这桶油怎么用"；分成三栏等于把一次取舍拆成三张清单给他做。
  代价是这一栏是面板里最长的一块：窄屏横带（844×390）上三族十二件全挂上时它已经贴着边界，
  而 v77 / v78 / v83 把「伏灯」「旋灯」「弃灯」那三栏也挂到同一个人身上之后（六族二十四件一起），
  手机上那条体检要量的横溢出现在**三块**面板上：所以每加一族，它都会连着把这三块各量一遍
  （那一屏存成 `17c-mobile-light.png`）。
- **「余烬风」是唯一一条"不咬血、只咬油"的险境，而它的解从 v66 起有两个**：火种永远比走路慢
  （0.75 → 0.95 倍脚力），所以**顺着风跑一定跑得掉**——这条规则是刻意钉死的
  （`tests/data.test.mjs` 里专门有一条断言 `speedEnd < 1`）：一个"到处都危险"的险境只会让人乱跑，
  而"危险有一个方向"才逼得出判断。代价是：横着走也基本安全（实测四秒 0 层），
  也就是说它**不是**一个"必须立刻处理"的险境，更像是给那八秒钟的走位加了一道划算不划算的账。
  另一条代价是它只在熔窟出现（一个十来分钟的局跑到第三关才见得到），
  所以它进图鉴、进关卡预告、进首遇提示卡——见不到的人至少能在图鉴里读到它长什么样。
  v66 补上了第二条解：**亮着的灯台会把扑到身上的火按灭**（每秒一层、站在光里也不再往上叠）。
  为什么要补：到 v65 为止，这条险境的答案只有一个键（冲刺），而"只有一个答案"的险境教会玩家的是
  一句口诀、不是一次判断。灯台本来就是这一局里最该被用起来的"据点"（长明、给余温、点亮它还会招来吹灯客），
  现在它多了一层意思。两条解花的东西不一样，这才是这条规则真正想给的选择：
  **冲刺花的是冷却**（立刻，但那条冷却本来要留给"躲开这一下"），**灯台花的是位置与时间**
  （跑过去、站三四秒，可灯台离出生点 620px 起、彼此隔 760px）。
  为什么不做成"灯台把火种吹开一圈"的泡泡：那等于把这八秒钟整个取消掉（站灯台边就没事了），
  而现在的规矩只有一条——**扑到身上的会灭**，风还在吹。
- **波次节奏：这一版动了，动的是一个先被台架量准的地方**（v66）：这条原本排在这儿等下一次，
  现在有了进仓库的台架 `tools/bench-waves.mjs`——脚本玩家跑完整局、逐波记下"时间花在哪一段"，
  两种走位成对看（`holder` 守着交战距离、绝不主动去追；`chaser` 永远压向最近的那一只），
  `--fixed` 还能钉死一套火力（同一套武器、不升级）做改前改后的 A/B：
  自然局里玩家会随击杀节奏抽到不一样的升级卡，两次跑出来连波数都不一样，差值里混着"构筑运气"，
  量不出规则本身的效果。
  它先量出来的数是：第一关一波平均 **26.0 秒**，其中**刷怪只占 4.6 秒**、清场 20.7 秒；
  场上只剩 ≤2 只的那段尾巴平均 **8.3 秒、最长 62.4 秒**；"350px 内一只怪都没有"的时间占整局 **33.5%**
  （单波最长 42 秒）。尾巴里点名最多的是**走得最慢的那几只**——石守 34、喷糜者 40、游尸 52 px/s，
  而怪一律刷在玩家 **620~940px** 外，它们光是走过来就要 12~26 秒。那 33.5% 不是"没刷怪"，是"怪还在半路上"。
  于是加了「循灯」（`src/data/hunt.ts`）：一波刷完、场上只剩最后 4 只的时候，**还没到场的那几只直奔玩家**
  （离得越远脚力越足，最多 2.8 倍，但绝对速度永远低于走路），而且不再"保持距离 / 去扑灯台"。
  钉死火力之后 A/B：**尾巴 6.7 → 3.1 秒（p90 19.3 → 8.1）**、清场 14.9 → 10.8 秒、
  "350px 内没怪"的单波时长 13.3 → 9.6 秒（追着打那一档 11.6 → 9.6 秒），
  而"挨了多少打"在同一档（150 vs 152）——它只压缩"还在路上"的那一段，正在跟你打的那几只一点没动。
  自然局里也看得到同一件事：尾巴里**每次**出现的平均时长，喷糜者 23.0 → 3.9 秒、游尸 11.8 → 6.6 秒。
  （台架按"每次平均"报数，不报累计秒数：两次跑的局长度可以差一倍——规则会改变结局——
  累计值放一起比就成了"跑得久的那一次数字更大"，那是跑量，不是节奏。）
  三条边界写在 `data/hunt.ts` 里，也各有一条断言：`near`(300px，约等于灯火最亮时的视野) 以内一点不改
  （那是"隐身加速"，不许有）、绝对速度上限低于玩家基础步速（"循灯的那几只永远追不上走路的你"是恒等式）、
  首领不吃这一条（它有自己那一阶段，那么大一块突然加速也显得假）。
  **还剩什么**：整局仍有约 30% 的时间"350px 内没怪"，其中一部分是**设计**（走去下一场、顺手点灯台、
  捡地上的东西），一部分是台架自己的毛病（脚本没有寻路，撞墙就贴着墙走，那几段它其实卡住了）。
- **波次节奏（其二）：把生成环从"按平均脚力"改成"按到场时间"**（v66，接着上一条做）。
  上一条把"一波的尾巴"砍掉之后，回头再看那 33%，就能把它拆开了——台架这一次多报了两个数：
  **刷怪阶段空场** 和 **清场阶段空场**。钉死火力的一局里（8 颗种子、两边各 328 波、跑完四关），
  一波 23.0 秒里"350px 内没怪"有 8.7 秒，其中 3.2 秒在刷怪阶段（第一批还在路上，可以理解），
  **4.4 秒在清场阶段**——那个阶段怪已经全刷出来了，场上就是有东西，只是它们还在半路上。
  根因是生成环按"平均脚力"定：怪一律刷在 **620~940px** 外，可脚力差 4 倍（石守 34 / 疾影 132 px/s），
  于是最快的 5 秒到脸上、最慢的要走 27 秒。改成**距离 = 到场时间 × 自己的脚力**（`data/arrival.ts`，目标 9 秒）：
  慢的从近处出发、快的从远处出发，一起到场。钉死火力的 A/B：
  **清场 12.6 → 7.3 秒**、单波空场 **8.7 → 5.3 秒**（其中清场阶段那一段 **4.4 → 2.1 秒**）、
  一波总时长 23.0 → 17.7 秒；而**挨打整局反而更少**（1158 → 1020）——
  "从远处慢慢走过来"的那一段，玩家本来就既挨不着也打不着，这一条只是把它换成了交战时间。
  三条边界写在 `data/arrival.ts` 里：真正的近边界是 `max(min, 灯火半径 + margin)`——
  `min`(430px) 只是地板（大于灯火**常规**最亮时的 320px），灯火被叠到 500 上下时环会跟着往外让，
  于是"看得见就不许刷"是**恒等式**而不是权衡；`max`(940px) 就是原来那个环的外沿
  （**只许把慢怪往里拉，不许把任何一只推得更远**）；
  精英与首领不吃这一条——它们的登场是给玩家看的（预告 / 大字 / 顿帧），导演只在普通怪那条线上传脚力。
  找路的那个台架毛病仍然留着：它量出来的空场只会比真人的更高。

## 技术要点

- **自研引擎（从零实现）**：`core/Loop`、`Renderer`（Canvas2D + DPR 自适应）、`Camera`（跟随/屏震/缩放）、
  `Input`、`PostFX`（暗角、扫描线、故障切片、**泛光 Bloom**）、
  `LightSystem`（离屏光照贴图：黑暗叠加 + 挖光 + 暖色加光）、`Pool`（对象池）、`Random`（可复现随机）、
  `Storage`、`Settings`、`Textures`（运行时烘焙位图纹理）、`Decor`（主题布景）。
- **动态光照**：每帧生成光照贴图，玩家灯火半径随灯油实时变化，Boss 与熔岩另有独立光源。
- **WebAudio 程序化音频**：平静/战斗/Boss 三层自适应配乐 + 全套合成音效，首次交互后启动。
- **美术素材**：默认**零外部素材**——地形/墙体纹理在运行时烘焙成平铺位图（`core/Textures`），
  其余为程序化绘制。如需替换为 AI 生成的位图，把图片放进 `public/assets/` 并在 `core/Assets` 中加载即可
  （当前环境未提供图像生成工具，因此采用运行时烘焙方案）。
- **UI 主题层**：`src/styles/main.css` 末尾的 `v29` 主题只加类名、不改 DOM——同一套 `panel / btn / card`
  元素按族套上 `panel--banner / --vellum / --board / --stone / --rite`，四角黄铜件、装订针脚、
  刻度、蜡封都是 `::before / ::after` 与多层渐变画的，没有一张图片素材。
- **性能**：对象池、视野裁剪、DPR 上限、可开关的减少动态效果，以及一整套为软件光栅化/高分屏做的优化：
  - **动态分辨率**：按实测帧间隔做比例控制（`scale *= sqrt(目标帧时间 / 实测帧时间)`），0.45 秒一个采样窗口，
    内部渲染分辨率在画质上限的 50%~100% 之间自动升降；另有像素预算兜底，避免 4K + 2x DPR 直接把帧率打死。
  - **静态地面烘焙**：地面（径向渐变 + 碎石贴图）只与主题和关卡尺寸有关，烘焙成一张位图后按需重绘，
    省掉每帧对整块 3000×2200 区域的 pattern 填充（1280×720 下约 7ms/帧，像素级等价）。
  - **静态家具精灵化**：地面网格、墙（贴图主体 + 顶光渐变 + 暗面 + 描边 + 投影，每面墙十几个命令）
    同样一整局不动。网格并进地面那张烘焙图；墙烘成**每面墙一张精灵**——1:1 世界像素，
    投影外扩 12px 一起包进去（少留一点就会切掉影子，像悬空），放大缩小照旧交给相机变换；
    桌面档烘 2 倍再缩回来（高分屏上贴图不糊），掌上档保持 1 倍（省 4 倍显存，且那里画面本来就在缩小），
    另有 6M 像素的总预算兜住极端关卡。手机横屏每帧画布命令 **1605 → 1273 条**，
    其中地面那一块 **407 → 178 条**（`fillRect` 141.6 → 26.4、`createLinearGradient` 24.6 → 1.6）；
    `FROZEN=1` 固定场面实测整帧 **−1.35ms（手机 844×390 dpr1）/ −6.6ms（桌面 1440×810，−9.7%）**。
    真机 Chromium 逐像素比对（烘焙路径 vs 改前的逐面墙绘制）：手机最大差 1/255、桌面最大 5/255；
    兜底路径（建不出位图时逐面墙直接画）与改前**逐位相同**。
  - **后处理合并**：扫描线 + 冷色暗角两次全屏 multiply 合并成一张预乘遮盖层；泛光的两层加法叠加
    先在半分辨率小图上合并再整屏加一次——整屏「读改写」次数直接决定软件光栅化的开销。
  - **光照精灵化**：暗幕挖洞与暖光叠加各烘焙一张 256px 径向光斑，取代每盏灯每帧的
    `createRadialGradient` + 圆弧路径填充；光照贴图本身按设备像素（与主画布同分辨率）绘制，
    贴回去时是 1:1，不再多缩一次（2560×1440 @2x 实测帧时间 27.2ms → 24.0ms）。
  - **分辨率同步**：后备缓冲（`canvas.width/height`）恒等于 CSS 尺寸 × 动态倍率，
    窗口尺寸变化、画质档位变化、`devicePixelRatio` 变化（换屏 / 改浏览器缩放）都会立刻重贴。
    这条不能省：倍率恰好没变而缓冲停在旧尺寸时，浏览器会把旧缓冲拉伸到窗口大小，
    画面整体发虚、镜头中心也会偏（`tests/renderer.test.mjs` 专门盯这条）。
  - **性能档位（`core/Perf`）**：把「这台设备该怎么画」收在一处。掌上设备（主指针是粗的，或视口本来就窄，
    带触摸屏的笔记本不算）一套、桌面一套，各按低/中/高三档给出倍率上限、像素预算、光照贴图倍率、
    泛光降采样与层数、布景与粒子密度、帧率上限。逐项：
    - **光照贴图半分辨率**：暗幕挖洞是一张低频柔光，减半再放大几乎看不出，填充与叠加的像素只剩 1/4；
      同时按屏幕坐标**裁掉视野外的光源**（留 8px 余量），远处的灯不再白占填充率。
    - **泛光降采样与单层叠加**：手机档取 1/6 分辨率、只叠一层（整屏加法是这条链里最贵的一步）。
    - **暖色分级搭泛光的车**：暖光（玩家周围那层 5% 的橙光）和泛光都是**加法**叠加，而加法可结合——
      单层叠加时先把暖光画进 1/6 分辨率的泛光小图、再整屏叠一次，于是整屏的"读改写"少一整个。
      844×390 定分辨率下实测这一下就是 **4~6ms/帧（约 10%）**；暖光被放大 6 倍也没有分别
      （同一页里逐像素比对：均值 0.13/255、最大 2）。
    - **布景与粒子密度**：`generateLevel(stage, seed, detailScale)` 用**独立随机源**铺陈设——
      同一种子在手机与桌面上是同一张地图（墙 / 神龛 / 灯台一模一样），只有陈设疏密不同；
      粒子按密度抽样，且密度为 1（桌面档）时一行额外逻辑都不走，行为与从前逐位一致。
    - **帧率上限**：手机上钉 60fps，但只在显示器刷新率是 60 的整数倍时才真的限（120/240Hz 才限，
      90Hz 硬限会掉到 45fps，反而更卡）；刷新率取前 45 个 rAF 间隔的中位数。
    - **动态分辨率的手机多一档**：桌面降到 0.5 倍就够（大屏再降会糊），手机留到 **0.4**——
      横屏本来就只有 0.18MPx 上下，多出来的 20% 面积余量正好给"差一口气到 60fps"的机型。
      它只在实测帧时间确实够不着 60 时才会被走到：容器里手机档默认跑法因此从 27.8ms（36fps）
      掉到 **18.3ms（55fps）**（画面从 dpr0.75 降到 0.6，只在这台量不出的慢机器上发生）。
    - **地面网格一次描完**：横竖 36 条线原来逐条 `stroke`（144 条画布命令），现在合成**一条路径**
      一次描出来——像素结果逐位相同（同一页里比对：均值 0.002/255、最大 13 且只差在线的端点抗锯齿），
      命令数少一半。**踩过的坑**：把它烘进地面位图会省掉全部命令，但地面位图是 0.58 倍分辨率再放大的，
      网格线会被"抹淡"；改成 pattern 填充则要在软件光栅化下多烧十几个视口的像素（反而慢 6ms/帧）。
    - **放大取样别做滤波**：地面位图与光照贴图都是"低分辨率烘好、每帧放大贴回来"的。
      双线性放大要按**目标**像素逐个做滤波，一次整屏读改写就是几毫秒；掌上设备改成最近邻之后
      这一层几乎白送（冻结同一帧逐像素比对：光照贴图均值 0.06/255、最大 2；地面 0.65/255，
      差异全在石子边缘，硬边反而更像碎石）。**暖光精灵**（提灯周围那圈加法柔光，半径按世界坐标算，
      整屏算下来有 0.4MPx）同理：它是一张很柔的径向渐变，最近邻与双线性的差别只有 0.03/255（最大 4），
      定分辨率 dpr1 下整帧 **35.6ms → 30.6ms（−14%）**。泛光那 1/6 分辨率的小图不能这么干——6 倍放大
      会糊成马赛克（试过：最近邻虽然快 3 倍，但亮处会变成一块块方格）。桌面满档保持双线性
      （屏幕更大，看得更仔细）。判据收在 `LightSystem.setScale` 里：光照贴图半分辨率、或者自适应
      已经把倍率压到 1 以下，就算"这台设备在走近路"，暖光一起不做滤波。
    - **视野裁剪**：每个敌人都要起渐变、描边、画血雾，几十只一起就是几毫秒——屏幕外的直接跳过
      （留 200px 余量，装得下首领光环与出生弹出）；粒子同理。
    - **横屏闸门**：手机竖屏时盖一块提示牌并**停掉主循环**；装到桌面走 manifest 的
      `orientation: landscape`，已在全屏里时再补一次 `screen.orientation.lock`。
    - **返回键守卫（`ui/BackGuard`）**：掌上设备在战斗中 `pushState` 一条守卫、`popstate`
      接住 → 暂停；`sync()` 每帧先比再动（装了就不重复塞，离开战斗才 `history.back()` 吃掉它），
      非掌上设备整段空转。真机实测这一步的坑：`history.length` 在浏览器里**只增不减**，
      所以判据得看 `history.state` 而不是长度；守卫被玩家按掉之后指针已经回到原条目，
      这时**不能再** `history.back()`（否则直接把玩家送出页面），靠 `armed` 标记区分"是我们撤的"还是"玩家按的"。
    - **让开刘海与手势条**：横屏时挖孔屏的刘海落在**左右两侧**，正好压在状态栏和构筑芯片上；
      iPhone 那种底部手势条会压住连杀条。横屏下 `body.is-touch` 的 HUD 用
      `env(safe-area-inset-left/right/top/bottom)` 让开（桌面与老机型上这些值恒为 0，等于没写）；
      `viewportcheck` 会断言这几条 `calc()` 真被浏览器接受——写错的 `calc()` 会被整条丢掉，
      那时 HUD 会悄悄掉回默认位置。
    - **触屏的提示与指引**：手机上不显示键盘键帽（`Tab`），首局提示也说"右下角的冲刺有无敌帧"
      而不是"空格冲刺 / Q 燃爆"；横屏矮屏时提示卡从屏幕正中改成**夹在左右两列 HUD 之间**的顶上那条带
      （左沿 266 = 左上那一列的右沿 258 再让 8，右沿 vw-130；上沿 58 = 右上那一列（含暂停键）的下沿 57
      再让 1——都是量出来的），方位箭头与世界标签的活动环也跟着收进两列之间——
      画布在 DOM 之下，钻到那两列底下就真的看不见了。摇杆显示与否和性能档位共用同一套触屏判定
      （`core/Perf.isTouchDevice`），免得出现"按手机算性能、却不显示摇杆"的自相矛盾。
    - **卡片的分寸（v60 重做）**：同一句话还挂在屏幕上就不再叠一条（开局那串事件里"图鉴 +2 条"曾经同时出现两条），
      已经开始淡出（`is-out`）的那条不拦——那句话玩家其实已经看完了。剩下的规矩按屏幕分两档：
      **桌面**照旧堆叠（短公告最多 5 条，超了先摘最旧的），大屏看得下就看得到上下文；
      **掌上横屏**（`HUD.feedMode`：触屏 + 横过来 + 高度 ≤700）只有**一条横带**放得下卡片
      （左上是生命/灯油那一列、右上是记分那一列、屏幕正中是**你自己**——844×390 上玩家占 y 179..207），
      于是短公告与提示卡各占一条"车道"、**同一条车道上一次只讲一张**，多的排队，讲完一张再上一张；
      排队的短公告超过 3 条就从最旧的开始丢（它说的是"此刻"，拖十几秒等于没讲），
      提示卡一条都不丢（`Game.showTip` 早把它记进存档了，丢掉就是这一局永远学不到）。
      公告（关卡名 / 第 N 波 / 首领登场）在这条横带上和卡片**轮流用**：它一亮，正讲着的卡片退回队头，
      等它那 2.4 秒讲完再接着讲——三样东西叠在一起就是 v59 那张糊住玩家的截图。
      320~380 高的 SE 档横带更窄，连"一张提示卡 + 一条短公告"都放不下，两条车道合成一条（`oneLane`）。
      **v61 又补了一把尺子：端上屏之后量一次**（`HUD.fitCard`）。横带净空在 390 高的横屏上只有 ~117px、
      320 高时只剩 ~82px，而提示卡的正文长短差着四倍（"分灯"两行讲完、"掠影"要六行）——
      按屏幕高度在 CSS 里写死"最多几行"必然有一档会漏，844×390 就漏过（两张卡片叠到下沿 y=190，
      玩家头顶才 181）。现在按**真实行高**（从计算样式里问，不写第二个真值）把正文砍到刚好停在玩家头顶；
      而且只有它**独占**横带时才砍——横带上还挂着别人就整张退回队列，宁可晚两秒讲，
      也不为了早报一句"图鉴 +2 条"把教学卡砍掉半句（头一样长的那两张教学卡在手机上会带个省略号，
      屏幕上放不下的几行就是这么收住的）。跟着一起量出来的还有**落点**：
      `@media (max-height: 700px)` 那一档得和 `HUD.feedMode` 的 700 对齐——561~700（平板横屏）
      原来卡片还留在屏幕正中，1024×700 实测正好压住左上那一列（6×42px），844×700 更狠（96×42px）。
      卡片的停留 / 淡出改由 `HUD.updateCards(dt)` 用帧时间推（桌面与掌上是同一套，
      主循环里每帧都调，暂停面板上那句"按了返回键 · 已暂停"也才等得到）：
      无头桩件里的 `setTimeout` 只入队不执行，旧写法在离线测试里压根没淡出过；
      浏览器切后台时 rAF 本来也会停，用帧时间推，卡片就和游戏一起停、一起走。
      实测同一张 844×390 的开局截图：卡片覆盖率 **21.4% → 9%**，最下面那张不再掉到屏幕外（v59 是 y=413）；
      v61 再量一次"开场那 9 句话一次全堆上去"的场面：844×390 峰值覆盖 **10.9%**、压到玩家 **0 次**，
      568×320 是 **6.5% / 0 次**（长句现在会独占横带，所以单张看着比 v60 高一点——换来的是再也没有第二张叠到人身上）。
    - **方位指引的标签不打架**：同方向上的几个目标（手机横屏实测：两座祭坛夹着一座灯台）
      会把"祭坛 800""灯台 900"两行字直接叠成一团，读不出任何一个。现在每帧先 `measureText`
      量出标签实宽，再沿箭头法线按 `[0, 18, -18, 36, -36]` 依次让位，最后 `clamp` 回两列 HUD
      之间那条安全带里——让开之后仍然贴着各自的箭头，读起来还是一组，只是不再糊在一起。
    - **触感（`core/Haptics` · `CombatHaptics`）**：只在掌上设备上震（带触摸屏的笔记本不算），
      设置里能关，浏览器不给 API（iOS Safari）就安静跳过；节奏与节流都放在一处，
      节流用游戏自己的 dt 而不是 `performance.now`，于是它能在无头环境里被单测。
    - **屏幕常亮（`core/WakeLock`）**：只在掌上设备、且只在真正在玩的时候持有，页面切回前台自动补申请。
    - **HUD 只在值变了才碰 DOM**：血条宽度按 0.1% 取整后比对、时间 / 击杀 / 金币等文本逐项记忆，
      没有首领时那几行不去清 DOM——每帧无脑写 `style` / `textContent` 会让浏览器反复排队样式重算，
      容器里实测这一项就要 2.4ms/帧（手机上只多不少）。触屏那两枚冷却圈同理：
      角度按 **1/32 档**取整后再比，60fps 下也只有冷却中的那几秒会写，一圈 11° 的步进在 76px 的圆上看不出来。
  - 以上改动都用**整帧像素差分**验证过等价性（均值差 ≤ 0.02/255，最大 ≤ 14）。

## 测试与自检

```bash
npm run typecheck   # TypeScript 严格模式全量检查
npm run build       # 生产构建
npm test            # 无头冒烟测试
```

`tests/` 提供最小可用的 DOM / Canvas2D / WebAudio 桩件，因此无浏览器也能验证：引擎启动、
刷怪与击杀、升级三选一与重掷、通关一关、Boss 相位切换、元进度写入存档、死亡结算、无尽模式，
以及「无 `console.error`」「仅创建一个 `AudioContext`」等稳定性要求。
桩件里元素的 `addEventListener` 与 `dispatchEvent` 也**真的派发**，所以挂在画布上的那种输入
（例如"按住鼠标右键手动瞄准"）能在无头环境里整条走通——不是靠测试去戳私有字段
（见 `tests/pouraimdesk.test.mjs`：`mousedown(button 2)` → 主循环 → 这一瓢真的往指针那边飞）。
`innerHTML` 在这个桩件里只是一根字符串（解析不出元素来），所以"焦点环能不能落到某个按钮上"
那类事默认量不到；`installDomStubs({ focusables, backElement })` 可以塞一份**带着矩形与 dataset
的假元素**进去，于是"真键盘事件 → `Input` → 主循环 → 环 → 元素的 `click`"这整条路在无头环境里也走得通
（`tests/focus.test.mjs` 里那两条就是这么量的）。
